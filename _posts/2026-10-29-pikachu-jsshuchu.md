## 题目: Pikachu Cross-Site Scripting - XSS之js输出

## 题目描述
页面提供了一个输入框，询问喜欢的 NBA 球员。要求利用 XSS 漏洞让页面弹窗。本关的输入内容被输出到了前端 JavaScript 代码的变量中。

## 解题思路
当用户输入被放入 `<script>` 标签内部的变量或函数（如 `var player = '用户输入'`）时，常规的 `<script>` 或 `<img>` 标签会被当成普通字符串，无法被浏览器解析执行。
我们需要观察 JS 代码的上下文，利用代码中没有被转义的单引号或双引号，**闭合前面的字符串，注入自己的 JS 语句，并用注释符（`//`）将后面的残留代码注释掉**，从而让浏览器执行我们注入的代码。

## 解题步骤

**1. 探测环境（⚠️ 踩坑记录）**
* 输入普通字符（如 `kobe`），点击 submit 发现页面没有弹窗。
* 尝试输入常规的 XSS Payload：`<script>alert(1)</script>`，页面依然毫无反应，没有弹窗。
* **原因分析**：按 `F12` 查看网页源码，发现输入的内容并没有出现在 HTML 标签中，而是被放进了页面的 `<script>` 标签内部。类似这样：`var player = 'kobe';`。在这种上下文中，HTML 标签会失效。

**2. 构造专属 Payload（通关步骤）**
* 既然输入被单引号 `'` 包裹在 JS 字符串中，我们就尝试闭合它。
* 在输入框中输入以下 Payload：
  `'; alert(1); //`
* 点击 submit，页面成功弹出了警告框！
* **原理解析**：当这段代码被拼接到 JS 中，变成了：
  `var player = ''; alert(1); //';`
  * 第一个 `'` 闭合了前面的字符串。
  * `;` 结束了赋值语句。
  * `alert(1);` 作为独立的 JS 语句被浏览器执行。
  * `//` 将后面原有的闭合单引号和分号注释掉，防止页面报语法错误。

**3. 备选 Payload**
* 如果后端使用的是双引号包裹，可以尝试：
  `"; alert(1); //`
* 如果输入被放在了 `<script>` 标签中，可以尝试闭合整个标签：
  `</script><img src=x onerror=alert(1)>`

## 知识点总结
1. **JS 上下文注入**：XSS 漏洞不仅存在于 HTML 标签中，输出到 JavaScript 代码块（变量、函数参数、`document.write` 等）同样致命。针对不同上下文，必须构造特定的闭合 Payload。
2. **JS 闭合技巧**：利用单/双引号闭合字符串，用分号结束语句，再用 `//` 或 `/* */` 注释后续代码，是 JS 上下文 XSS 的核心套路。
3. **防御策略**：
   * 避免将用户输入直接拼接进 JS 代码。如果必须传递，使用 JSON 序列化并在后端严格转义。
   * 部署内容安全策略（CSP），限制内联脚本的执行。
   * 对输出内容进行 HTML 实体编码和 JS 编码。
