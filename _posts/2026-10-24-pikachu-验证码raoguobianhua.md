# 题目: Pikachu 暴力破解-验证码绕过 (on client)

## 题目描述
登录表单增加了验证码，但验证码的逻辑是在客户端（浏览器端/前端）处理的。题目要求绕过该机制，通过暴力破解获取正确的账号密码。

## 解题思路
“on client” 代表前端的校验。这类漏洞的典型特征是：验证码是由前端 JavaScript 生成并校验的。
因此，绕过它的核心思路是：**抓取登录请求包，直接删除（或忽略）验证码参数，只对账号和密码进行爆破**。因为后端根本没有对验证码进行真正的强校验。

## 解题步骤

**1. 观察与踩坑记录**
*   页面上的验证码直接以文本形式显示（例如 `DMUO6`）。
*   **⚠️ 踩坑发现**：刷新页面后，发现验证码居然会**动态变动**！这说明验证码并非完全写死在 HTML 里，而是由前端 JS 随机生成的。
*   既然会变动，直接通过修改前端源码硬编码绕过可能失效。我们需要去抓包，看看服务器到底有没有校验这个参数。

**2. 抓包并删除验证码参数**
*   开启 Burp Suite 拦截。
*   随便输入账号 `admin`、密码 `123`，**填入当前页面上正确的动态验证码**，点击 Login。
*   在 Burp 中拦截到 POST 请求。观察请求体：`username=admin&password=123&vcode=当前验证码...`
*   **关键绕过步骤**：在请求体中，**直接把 `vcode=...` 这个参数删掉**。
*   将请求发送至 **Intruder** 模块。

**3. 配置爆破**
*   在 **Positions** 标签页，清空所有标记，给**账号**和**密码**都加上变量标记（采用上一关教过的 `Cluster bomb` 双变量交叉爆破）。
*   去 **Payloads** 标签页：
    *   **Payload set 1 (账号)**：填入 `admin`、`test`、`pikachu`。
    *   **Payload set 2 (密码)**：填入 `123456`、`abc123`、`000000` 等常见弱口令。

**4. 发起攻击与分析**
*   点击 **Start attack**。
*   观察返回结果。因为我们在请求中删除了验证码参数，如果后端没有报“验证码不能为空”的错误，而是乖乖去校验了账号密码，说明漏洞利用成功！
*   通过观察 **Length（响应长度）** 排序，找到长度异常的行，成功爆破出正确的组合：
    *   `admin` / `123456`
    *   `test` / `abc123`
    *   `pikachu` / `000000`

**5. 验证登录**
*   回到网页，输入任意一组正确的账号密码，成功登录通关。

## 知识点总结

1. **客户端校验的脆弱性**：任何在浏览器端（前端 JS）进行的验证、校验都是不可信的。攻击者可以轻易查看源码、抓包篡改甚至直接删除参数。
2. **验证码的生成与校验机制**：
   *   本关卡中，验证码虽然会动态变化，但仅仅是在前端生成，或者后端并没有将其与用户的 Session 强绑定，导致攻击者抓包后直接删除该参数即可绕过。
3. **防御策略**：**所有的安全校验都必须在服务器端进行**。服务器必须生成验证码、保存到 Session 中，并在每次登录请求时严格比对，无论校验成功还是失败，都必须立刻销毁该验证码，防止重放攻击。
