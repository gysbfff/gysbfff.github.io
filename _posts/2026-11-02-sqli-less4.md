## 题目: Sqli-labs Less-4

## 题目描述
页面提示输入 ID 参数进行查询。本关的注入点不仅变成了双引号，还增加了括号，要求利用特殊的闭合方式绕过，获取数据库敏感信息。

## 解题思路
这关名为 `Double Quotes - String`。我最初尝试只用双引号 `"` 闭合，结果页面直接报错。结合上一关的经验，我推测后端 SQL 语句是 `select ... where id = ("$id")` 这种形式。因此，我必须用 **`")`** 组合来同时闭合双引号和括号，才能让逃逸成功。

## 解题步骤
**1. 测试闭合方式与原理分析（⚠️ 踩坑记录）**
* **原理解释**：搞清楚后端是如何包裹我们输入的，是注入成功的前提。这关既然是双引号，我先试了双引号。
* **踩坑记录**：我在地址栏输入 `?id=1" --+`，页面直接报错 `near '"' at line 1`。这说明双引号生效了，但是语法依然断裂，暗示前面有括号。
* **破局**：我尝试了组合闭合 `?id=1") --+`，页面成功回显了 `Dumb`。说明闭合符就是双引号加右括号 `")`。

**2. 判断字段数**
* **原理解释**：利用 `ORDER BY` 试探列数，一旦数字超过实际列数，数据库就会报错。
* **实战操作**：我测试了 `?id=1") order by 3 --+`，页面正常。接着测试 `?id=1") order by 4 --+`，页面报错。由此确认当前表有 **3 个字段**。

**3. 联合查询爆数据（Payload 拆解原理）**
* **原理解释**：为什么 Payload 要这么写？因为它像是一个“特洛伊木马”：
    * `-1")`：先用 `-1` 让原查询为空，再用 `")` 闭合后端代码，让后续语句顺利执行。
    * `union select 1,2,3`：联合查询，凑齐 3 个字段，找到网页的回显位（第 2 和第 3 位）。
    * `group_concat(username,0x3a,password)`：把所有账号密码用冒号（`0x3a`）拼成一行。
    * `from users`：指定目标表。
    * `--+`：把后端多余的代码注释掉。
* **实战 Payload**：
    ?id=-1") union select 1,group_concat(username,0x3a,password),3 from users --+
* **结果**：页面成功爆出所有用户的账号和密码，第四关拿下！

## 知识点总结
1. **闭合符号的多样性**：SQL 注入的闭合符号不局限于单引号，还可能包括双引号、括号，甚至组合起来使用。实战中需要通过报错信息不断试探。
2. **注释符的作用**：`--+` 用于将后面多余的 SQL 代码注释掉，防止语法错误，是注入中必不可少的技巧。
3. **防御策略**：使用 PDO 预编译，避免 SQL 语句拼接。
