## 题目描述
访问页面发现存在.git目录泄露，通过下载git仓库，查看提交历史找到flag。

## 解题思路
1. 检测网站存在`.git`目录泄露，使用git-dumper拉取完整仓库。
2. 拉取仓库后，使用`git reflog`查看所有HEAD变动记录（包括被reset丢弃的提交，`git log`看不到）。
3. 依次查看commit：
    - fdce35：flag被修改为假flag `flag{nonono}`
    - 40c6d51：原始提交，存放真正flag
4. 使用`git show [hash]`读取提交内容，获取flag。

## 操作步骤
1. 用阿里镜像下载git
2. 在cmd中寻找哈希
3. 依次以git show+哈希的形式寻找flag
4. 最终找到flag

## 知识点
1.使用清华镜像
-清华镜像不支持git clone/github仓库加速，不要拿它拉取git源码
2. Git 提交哈希（Hash）
-Git 每一次  commit  提交都会生成一串唯一的字符编号，叫做哈希，由字母和数字组成，相当于本次提交快照的身份证。只要提交内容发生变化，哈希值就会改变。使用时只需要填写前7位简写即可定位对应的提交。通过  git reflog  可以查看所有提交记录，每行最左侧的字符串就是哈希。搭配命令  git show 哈希值 ，可以查看这次提交的文件修改、提交备注等全部信息。
3. Git 版本回退与 reflog
-使用  git reset  回退版本后，旧提交在  git log  中会消失，但并不会直接删除。 git reflog  可以记录 HEAD 所有的操作轨迹，找回被 reset“隐藏”的提交，这是本题核心考点。
4. Git源码泄露漏洞
-网站上线时若没有保护  .git  目录，攻击者可以下载整套Git仓库，获取全部文件与完整历史提交记录。开发者上线项目严禁对外暴露  .git  文件夹。
5. flag藏匿技巧
-flag不一定写在文件修改（diff区域）中，也可以直接写在commit的提交描述里，做题时查看提交记录需要完整阅读所有信息，不要遗漏备注内容。
6.哈希：哈希（hash）就是一串由字母+数字组成的唯一编号，Git 给每一次代码提交分配这个编号。

## 判断git源码泄露
 
1. 访问网站的  /.git/  路径
在网址后面加上  /.git/ ，如果页面可以正常访问、能列出目录，就说明存在Git源码泄露。
示例： http://xxx.xxx.xxx:xxxx/.git/ 
2. 特征文件检测
 .git  目录下存在固定文件，访问下面任意文件能返回内容，即可确认：
 -  /.git/config 
-  /.git/HEAD 
-  /.git/index 
 3. 工具验证
     可以使用  git-dumper  这类工具，尝试下载仓库。如果能成功拉取仓库文件，代表漏洞存在。
 (原理：Git仓库的所有版本、提交记录都保存在 .git 文件夹。服务器没有配置访问限制，外部用户可以直接下载这个文件夹，拿到源代码和全部提交历史。)

## 总结
1.本题考察Git源码泄露漏洞。网站对外开放了 .git 目录，攻击者能够下载完整仓库与全部版本历史。题目利用 git reset 进行版本回退，将包含真实flag的提交隐藏，直接查看当前文件或者使用 git log 无法找到flag。
2.解题核心是使用 git reflog 查看HEAD全部操作记录，获取历史commit的哈希值，再通过 git show [哈希] 查看对应提交详情。需要注意flag不一定存放在文件改动区域，也可能写在commit提交备注中，阅读信息不能只看diff部分。
3.同时在实操中要留意：短时间大量批量拉取仓库文件，在校园网环境容易触发网关风控，导致镜像站访问被拦截。开发上线网站时，切记禁止对外暴露 .git 目录，防止源代码与历史提交信息泄露。
4.风险：一旦存在 .git 泄露，攻击者不仅能拿到当前源码，还可以通过 git reflog 回溯所有历史提交，找到曾经提交过的敏感信息，例如账号、密钥、flag。网站部署时，一定要禁止访问 .git 目录。
