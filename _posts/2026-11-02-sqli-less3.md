## 题目:Sqli-labs Less-3 - 基于报错的 GET 单引号+括号闭合注入

## 题目描述
页面提示输入 ID 参数进行查询。本关在后端代码的注入点外层增加了括号，要求利用特殊的闭合方式绕过，获取数据库敏感信息。

## 解题思路
这一关的名字带了个 `twist`（曲折/转折），我猜测后端 SQL 语句不会像前两关那么简单，大概率是给参数加上了括号，类似 `select ... where id = ('$id')` 这种形式。如果按常规思路只用单引号闭合，肯定会报错。所以我必须想办法把那个多出来的右括号也一起闭合掉。

## 解题步骤
**1. 测试闭合方式与原理分析（⚠️ 踩坑记录）**
* **原理解释**：做 SQL 注入的第一步，就是搞清楚后端是怎么把我们的输入包裹进 SQL 语句的。如果是 `id='$id'`，就用单引号闭合；如果是 `id=('$id')`，那就得连括号一起闭合。
* **踩坑记录**：我先尝试输入 `?id=1'`，页面直接报错。于是我又加上了注释符，输入 `?id=1' --+`，结果页面**依然报错**。我意识到，虽然单引号闭合了，但语句里多出来的那个右括号依然破坏了语法结构。
* **破局**：既然多了个括号，那我就给它补上。我尝试构造了 `?id=1') --+`，按回车后，页面竟然成功恢复正常回显了 `Dumb`！这证实了我的猜测，后端的闭合符就是 `')`。

**2. 判断字段数**
* **原理解释**：我用 `ORDER BY` 语句试探列数，因为它是按列的数字索引排序的。如果数字超出了实际列数，数据库就会报错。
* **实战操作**：因为前面已经确认了闭合符是 `')`，这次我可没忘带上括号。
* 我测试了 `?id=1') order by 3 --+`，页面正常回显。
* 接着测试 `?id=1') order by 4 --+`，页面报错了（提示 `Unknown column '4'`）。由此我推断出，当前查询结果共有 **3 个字段**。

**3. 联合查询爆数据**
* **原理解释**：`UNION SELECT` 要求前后两个查询的列数必须一致。我用 `-1` 让前面的正常查询结果为空，这样页面就只会显示我 UNION 查询出来的数据。
* **实战操作**：我构造了 Payload，用 `group_concat` 把多行的账号密码拼成了一行，方便一次看全：
    ?id=-1') union select 1,group_concat(username,0x3a,password),3 from users --+
* **结果**：页面成功回显出数据库中所有用户的账号和密码（如 `Dumb:Dumb, admin:admin` 等），第三关拿下！

## 知识点总结
1. **闭合与上下文**：在进行 SQL 注入时，必须根据后端的代码结构（如是否包裹了单引号、括号）来构造对应的闭合符号。这一关考验的就是我对代码结构的推理能力。
2. **Twist 关卡特点**：这类关卡通常通过加括号、加转义等方式增加难度，盲目套用前两关的 Payload 是行不通的。
3. **防御策略**：使用 PDO 预编译，避免 SQL 语句拼接。
