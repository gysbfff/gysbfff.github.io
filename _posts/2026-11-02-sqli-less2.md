## 题目: Sqli-labs Less-2

## 题目描述
页面提示输入 ID 参数进行查询。本关要求利用数字型 SQL 注入漏洞，获取数据库中的敏感信息。

## 解题思路
本关是经典的 GET 型数字注入。与第一关（字符型）不同，后端在拼接 SQL 语句时，没有用单引号将参数包裹起来（即 `id=$id` 而不是 `id='$id'`）。
因此，我们**不需要闭合单引号**，可以直接在数字后面拼接 `order by` 判断字段数，再使用 `UNION SELECT` 联合查询，把我们要的数据强行拼接到页面上回显。

## 解题步骤
**1. 确认正常回显**
* 访问 `?id=1`，页面成功回显 `Your Login name: Dumb`，确认查询正常。

**2. 判断字段数（原理：探测列的数量）**
* **原理**：`ORDER BY` 语句是按照列的数字索引进行排序的。如果表中只有 3 列，你让它按第 4 列排序，数据库就会报错。
* 访问 `?id=1 order by 3 --+`，页面正常显示。
* 访问 `?id=1 order by 4 --+`，页面报错 `Unknown column '4' in 'order clause'`。由此推断，当前查询结果共有 **3 个字段**。

**3. 联合查询爆数据（原理：强行拼接）**
* **原理**：原查询是 `select ... where id = -1`，因为 id 为 -1 的数据不存在，所以前半段查询结果为空。接着用 `UNION SELECT 1,2,3` 拼接，页面会将第 2 和第 3 个位置的数据回显出来（第 1 位由于通常只显示用户名，所以放占位符 1）。
* 在地址栏构造以下 Payload：

    ?id=-1 union select 1,group_concat(username,0x3a,password),3 from users --+

* **结果**：页面成功回显出数据库中所有用户的账号和密码，如 `Dumb:Dumb, Angelina:I-kill-you, admin:admin` 等，注入成功。

## 知识点总结
1. **数字型与字符型的核心区别**：数字型不需要单引号闭合，直接拼接 SQL 逻辑即可。
2. **`ORDER BY` 的探测作用**：不仅是用来排序，在注入中常用来判断当前 SQL 语句查询了多少列，这是 `UNION SELECT` 成功的前提。
3. **防御策略**：
   * 对传入的 ID 强制进行整数转换（如 `intval()`）。
   * 使用 PDO 预编译（Prepared Statements），从根源上杜绝 SQL 注入。
