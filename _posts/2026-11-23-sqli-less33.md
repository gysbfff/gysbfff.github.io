## 题目: Sqli-labs Less-33

## 题目描述
页面提示 `Please input the ID as parameter with numeric value`。底部有 `Hint` 回显，会展示你输入的字符被转义后的样子，以及对应的十六进制编码。本关与 Less-32 类似，同样存在 `addslashes` 转义防御。

## 核心原理与前置分析
本关的考点依然是**宽字节注入**。
后台使用 `addslashes()` 将单引号 `'` 转义成了 `\'`。但在 GBK 编码环境下，我们输入 `%df`，后台加上反斜杠后变成 `%df%5c`，刚好拼成一个合法的汉字（“運”），从而把反斜杠 `\` 吃掉，成功释放出单引号进行闭合。

*(注：Less-33 官方源码中多了一些 `htmlspecialchars` 等处理，但在本地靶场环境下，`%df` 宽字节的打法依然完美适用。)*

## 解题步骤
**1. 踩坑与复盘（⚠️ 真实踩坑记录）**
* **踩坑一：常规闭合完全失效**。输入 `?id=1'` 时，后台把它当成了纯字符串处理，页面直接回显了正常的 `Dumb`，没有任何报错。因为转义符 `\` 把单引号变成了普通字符。
* **踩坑二：多余字符导致语法崩溃**。在查表名时，由于不小心在 URL 中多输入了一个斜杠 `/`，导致后台 SQL 语法直接崩溃，`Hint` 提示完全为空，误以为是被 WAF 拦截。
* **破局**：去掉多余字符，保持 `%df'` 与后台自带的 `'` 和 `LIMIT` 完美闭合。

**2. 爆表名（宽字节逃逸验证）**
* **输入 URL**：`?id=-1%df' union select 1,group_concat(table_name),3 from information_schema.tables where table_schema=database() --+`
* **回显现象**：页面成功回显表名 `emails,referers,uagents,users`。

**3. 终极脱库（提取数据）**
* **输入 URL**：`?id=-1%df' union select 1,group_concat(username,0x3a,password),3 from users --+`
* **回显现象**：页面瞬间爆出所有账号密码，包括 `Dumb:Dumb, Angelina:I-kill-you...` 以及之前注入留下的 `admin'#` 等历史数据。

## 知识点总结
1. **宽字节注入的普适性**：只要数据库编码是 GBK 等双字节编码，且使用了 `addslashes`，这种漏洞就极其常见。
2. **通杀 Payload**：在掌握了 `%df` 绕过原理后，Less-32 和 Less-33 的解法是完全一致的。
3. **联合查询脱库**：在确认闭合成功后，利用 `UNION SELECT` 配合 `group_concat` 是最直接、最高效的脱库方式。
