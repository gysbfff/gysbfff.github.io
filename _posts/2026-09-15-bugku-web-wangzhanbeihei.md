# 题目： Bugku CTF 网站被黑

## 题目描述
访问靶场首页直接展示篡改页面“中国灰客联盟，你的网站存在漏洞，请及时修复！byharry”，页面没有任何输入框，没有交互按钮。题目提示网站遭到入侵，黑客可能留下后门文件，需要找到后门拿到flag。

## 解题思路
1. 访问首页，页面只是一张静态篡改黑页，`Ctrl+U`查看网页源代码，页面源码里面没有注释、base64字符串、密码等线索。
2. 根据题目名字“网站被黑”进行判断：黑客入侵网站之后上传了Webshell小马后门，考点是目录扫描寻找隐藏php文件。
3. 使用目录扫描脚本探测，发现 `/shell.php` 存在，访问该路径出现密码输入界面。
4. 页面没有给出任何密码hint，判断属于弱口令爆破类题目，使用常见弱口令字典尝试登录，成功得到密码为`hack`。
5. F12查看input标签，确定表单提交参数名称是`pass`，POST提交数据包验证密码，成功拿到flag。
-为什么密码是hack：
> 这道题的密码并不是通过解密、编码转换推导出来的，属于出题人预设的固定弱口令。
> 模拟真实环境：很多黑客上传的webshell小马，会设置简单密码方便自己后续登录，`hack`、`admin`、`123456`都是后门程序高频弱口令。
> 在没有任何密文、提示的场景下，就可以使用弱口令字典进行爆破测试。

## Python解题脚本（带详细注释）
```python`
# 导入requests库，构造POST数据包提交webshell密码
import requests
# 修改为你自己的靶场IP和端口
base_url = "http://xxx.xxx.xxx.xxx:xxxx"
url = base_url + "/shell.php"
# 重点：F12查看input标签，表单name是pass，不是pwd！密码hack
post_data = {
    "pass": "hack"
}
# 发送POST登录请求
resp = requests.post(url, data=post_data)
# 打印返回页面，提取flag
print(resp.text)


## 踩坑记录
1. 惯性思维坑：上一题考察XFF请求头伪造，一开始思维定势，疯狂添加X‑Forwarded‑For请求头尝试绕过首页，完全无效，浪费大量时间。
2. 死磕首页源码：一直在首页页面反复Ctrl+U寻找密码、base64，忽略了Web类黑页题的套路，没有第一时间启动目录扫描。
3. 参数名称坑：想当然写参数 pwd 提交数据包，密码虽然正确，但是参数名和前端表单不一致，一直登录失败；必须F12确认input标签的name属性。
4. 字典坑：爆破能否成功取决于字典内容，如果字典里面没有hack，无论跑多久都无法爆出密码。
5. 靶场时效坑：Bugku靶场拥有存活时间，超时后IP失效，所有路径访问全部404，需要重新启动场景更新url。
 
## 知识点总结
1. 网站黑页类CTF Web题，做题思路优先为：查看源码 → 访问robots.txt → 目录扫描，寻找黑客遗留的webshell后门文件。
2. 目录扫描本质是字典爆破，拼接路径批量发包，一般状态码200代表文件真实存在；403代表路径存在但是禁止访问，同样值得进一步探测。
3. 做题区分两种密码来源：有hint密文就解密推导密码；无hint+后门登录界面，优先考虑弱口令爆破。
4. Web提交POST数据包前，一定要确认表单input的name属性，不能仅凭自己主观猜测参数名。
5. 常见后门文件名：shell.php、ma.php、backdoor.php；高频弱口令：hack、admin、123456、test、root。
